# 0001. 記録の置き場所を Issues・ADR・ワークログに分ける

- 状態: 採用
- 日付: 2026-11-02

## 背景

- 開発期間は 6 日で、1 人で作る
- 審査の「深さと実行力」（20%）はリポジトリを見て判断される。試行錯誤の跡と、課題にじっくり向き合った跡が問われる
- ルールでは、期間前に作ったものは使えない。何をいつ作ったかを、外から追えるようにしておきたい
- 提出物は 6 つあり、送信したあとは変更できない。出し忘れを防ぎたい

## 決めたこと

記録の種類ごとに置き場所を分け、すべてこの公開リポジトリの中に置く。

| 記録                         | 置き場所                                                      | 単位                |
| ---------------------------- | ------------------------------------------------------------- | ------------------- |
| やること・不具合・決めること | GitHub Issues。提出に要るものはマイルストーン「提出」に入れる | 1 件ずつ            |
| 設計の判断とその理由         | `docs/adr/`                                                   | 1 判断で 1 ファイル |
| その日の作業                 | `docs/worklog/YYYYMMDD.md`                                    | 1 日で 1 ファイル   |
| 提出物の下書きと状態         | `docs/submission/`                                            | 項目ごと            |
| Claude Code への指示         | `CLAUDE.md`                                                   | 1 ファイル          |

## 検討したほかの案

| 案                                               | 採らなかった理由                                                           |
| ------------------------------------------------ | -------------------------------------------------------------------------- |
| 普段使っている非公開のタスク管理ツールで管理する | 審査員から見えない。期間中に作った記録として示せない                       |
| GitHub Projects のボードを作る                   | 1 人で 6 日なら、Issues とマイルストーンで足りる。管理の手間のほうが大きい |
| README だけに書く                                | 判断の理由と日々の経過が埋もれ、あとから追えない                           |

## 結果

- 審査員がリポジトリだけで、課題・判断・経過を追える
- 作業の区切りごとにワークログと ADR を書く手間が増える。CLAUDE.md に決まりとして書き、Claude Code にも書かせる
- 提出物は `docs/submission/` で状態を見て、出し忘れを防ぐ
