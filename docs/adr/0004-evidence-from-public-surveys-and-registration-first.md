# 0004. 聞き取りを公的調査に置き換え、「困った日には間に合わない登録」を第一声にする

- 状態: 採用
- 日付: 2026-11-04
- 関連: [ADR 0002](0002-topic-gaps-left-by-existing-apps.md)（見直す条件をこの ADR で置き換える）、[spec.md](../spec.md)、#8、#10

## 背景

- ADR 0002 は「11/3〜4 に 3 人以上へ聞き取り、知らずに損をした・慌てた例がほとんど出なければ題材を見直す」を見直す条件にしていた。11/4 の時点で聞き取り（#8）は 1 件も行えていない。残りは 4 日で、コードはまだ無い
- 代わりに公的調査を確かめた
  - 東京都 子供・子育て会議 病児保育部会（2026-09-08、保護者 6,181 人が回答）: 病児保育の事前登録をしていない 66.5%。子が病気で預け先に困った経験 85.1%。病児保育を利用したのは 18.5%。核家族 81.5%（[議事録](https://www.fukushi.metro.tokyo.lg.jp/documents/d/fukushi/02gijiroku-pdf)）
  - 函館市 病児保育事業アンケート（2025-12、保護者 1,454 人が回答）: 知っている人のうち利用か登録をしたことがあるのは 5.2%。使わなかった理由の 2 位が「事前登録をしていなかった」39.3%、その人たちの 62.9% は「利用したい」。重視する点の 1 位が「事前登録・予約手続きの簡便さ」63.3%（[報告書](https://joruri-cms.city.hakodate.hokkaido.jp/docs/2025082200054/file_contents/byouji_tyousakekka.pdf)）
  - 母子保険はぐ 妊婦調査（2023-03、3,287 人）: 妊娠・出産のお金に不安 76.7%。改正育児・介護休業法を知らない 50%（[プレスリリース](https://prtimes.jp/main/html/rd/p/000000283.000012138.html)）
  - 札幌市の出生数は年約 1 万人。2 年連続で 1 万人を割った（[北海道新聞](https://www.hokkaido-np.co.jp/article/1280065/)）
- 競合が出ていた。LINE ヤフー「Agent i 子育てエージェント」（[2026-10-14 提供開始](https://www.lycorp.co.jp/ja/news/release/020891/)、LINE 内）。愛称・生年月日・居住エリアから、月齢順の「子育てロードマップ」と、自治体の手続き・助成金の TODO を AI が作る。母子手帳や通知の撮影読み取り、知恵袋つきのチャットがある。一方で「生成 AI の出力の正確性・完全性は保証しない」と明記し、出典・確認日・期限の計算・通知は無い。預け先の事前登録と、親の働き方の軸も無い
- 題材を「病気・休業時の手続き」（[docs/research](../research/cancer-experience-facts-20261103.md)）に切り替える案も検討した
- 札幌市の 4 月入所の 1 次調整の締切は 2026-11-30 17:15 必着（[札幌市](https://kosodate.city.sapporo.jp/mokuteki/azukeru/hoiku/ninka/8935.html)、11/4 確認）。デモ日 11/8 に「締切が近い」になり、spec §9 の流れが成り立つ

## 決めたこと

1. **題材は維持する。ニーズの根拠は当事者の聞き取りではなく公的調査に置く。** #8 は閉じる。ADR 0002 の「見直す条件」はこの ADR で置き換える。初版を札幌の親 3 人に見せて見落としが出るかを確かめるのは、大会のあとに行う
2. **第一声は「困った日には間に合わない登録を、先に済ませる」。** 預け先の事前登録を優先 1 に上げる。手続き・お金と任意接種は変えない。Agent i との違いは、預け先の事前登録・親の働き方の軸・プログラムで計算した期日・出典と確認日・個人情報をサーバーに置かないこと、の 5 つで言う
3. **計算した開始日と締切を iCalendar（.ics）に書き出せるようにする。** 通知は作らない（spec の前提は変えない）。端末のカレンダーに入れれば、開かなくても締切が届く。サーバーも個人情報の送信も要らない
4. **#10（制度データの初版）に着手する。** 領域ごとのサブエージェントで公式ページから起こし、候補の一覧を人が見て選ぶ。日付計算のコードは今日は書かない

## 検討したほかの案

| 案                                                                 | 採らなかった理由                                                                                                                                                                                                               |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 今日〜明日で 3 人に聞いてから進める                                | 聞き終わるまで実装が止まる。11/6 に通しで動く目標に届かない                                                                                                                                                                    |
| 題材を「病気・休業時の手続き」に切り替える                         | 作者の深さはあるが、公的な数字が薄く（高額療養費の仕組みを理解していた人 37%、n=362、[患者家計サポート協会](https://media.moneyforward.com/articles/9927)）、医療の助言との境界に近い。聞き取りも無いまま 4 日で作るのは厳しい |
| 現案をそのまま進め、Agent i との違いは README で説明するだけにする | 手続きとお金の一般的な TODO は Agent i と重なる。重ならないところを先頭に出さないと、デモで差が伝わらない                                                                                                                      |
| 使われる仕掛けとして LINE 通知を足す                               | サーバーに家庭の情報を置くことになり、spec §4 と矛盾する。4 日では重い                                                                                                                                                         |

## 結果

- README とデモの冒頭で言い切る文言が決まった。Agent i との違いを README に書く（#6）
- 当事者の声が無いまま提出することになる。公的調査の数字で補い、大会のあとに 3 人へ見せる
- 作るものが 1 つ増える（.ics 書き出し）。半日の見込み。間に合わなければ削る
- ADR 0002 の状態は「採用」のまま。見直す条件だけがこの ADR に移る
