# 0006. 開いたときは「今月と来月」だけを出し、設定の最後に期日をカレンダーへ書き出す

- 状態: 置き換え（0011）
- 日付: 2026-11-05
- 関連: [ADR 0005](0005-twelve-month-outlook-as-main-screen.md)（初期表示の範囲と削る順をこの ADR で変える）、[ADR 0004](0004-evidence-from-public-surveys-and-registration-first.md)、[spec.md](../spec.md)、#16、#17、#20、#22

## 背景

- 11/4 の夕方に、初版の制度データから架空の家庭の 12 か月の見通しを紙で組み、作者（n=1）に見せた。知らなかった項目は 2 件出た（ADR 0004 の結果）が、「この形では自分の家庭では使わないと思う」とも答えた
- 11/5 に理由を聞いた。2 つ: **自分から開かない**（Web を月 1 回でも自分から開く習慣がつかない。カレンダーや通知に入ってくるなら使う）、**表が多すぎる**（12 か月 × 3 レーンは情報が多い。要るのは今月と来月に先に済ませることだけ）
- spec の前提は「通知は作らない。毎月 1 日に開くよう案内する」だった。ADR 0004 で .ics の書き出しを足したが、ADR 0005 では削る順の最後に置いていた（第 2 子 → 起きうることの数字 → .ics）
- 公的調査でも、病児保育で重視される点の 1 位は「事前登録・予約手続きの簡便さ」63.3%（函館市、ADR 0004）。開く手間と読む量が、そのまま使われない理由になる

## 決めたこと

1. **開いたときの初期表示は「今月と来月」の 2 か月だけ。** 各月は「先に済ませること」を先頭に、期日の近い順。起きうることとお金は各月 1 行ずつに畳み、開くと広がる。12 か月の見通しは同じ画面の下に置く（下に送るか「12 か月を見る」）。ADR 0005 の 3 レーン・12 か月・レバーは変えない。変えるのは最初に目に入る範囲と順番だけ
2. **.ics の書き出しは削らない。** 削る順は 第 2 子 → 説明文 → 起きうることの数字 にする。.ics は病児保育の登録と同じく、どの関門でも残す
3. **最初の設定の最後の案内を「毎月 1 日に開く」から「今月と来月の予定をカレンダーに入れる」に変える。** 押すと .ics を書き出し、端末のカレンダーに入る。ホーム画面への追加はその次に案内する
4. **.ics には、期日のほかに「毎月 1 日に さきよみ を開く」の繰り返しの予定を 1 件含める。** 開く習慣を端末のカレンダーに持たせる。サーバーも通知の仕組みも要らない。要らない人は外せる

## 検討したほかの案

| 案                                               | 採らなかった理由                                                                                                 |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| LINE やメールで通知する                          | サーバーに家庭のデータを置くことになる（ADR 0004 で却下済み）                                                    |
| Web Push（サービスワーカー）で通知する           | 購読の保存先と送信の仕組みが要る。iOS はホーム画面への追加が前提。4 日では重い                                   |
| 12 か月の表を主画面のまま、色と文字の量だけ減らす | 読む量は減るが、最初に 12 か月分が目に入ることは変わらない。「表が多すぎる」に答えていない                       |
| 今月だけを出す                                   | 来月の締切（例: 4 月入所の申込は 11/30）が見えない。「困った日には間に合わない登録を先に済ませる」に合わない     |
| 12 か月の見通しをやめて TODO の一覧に戻す        | 作者が「シミュレーターがよい」と出した方向（ADR 0005）を覆す。見落とし 2 件は 12 か月の表から出た               |

## 結果

- 作るものは増えない。初期表示の範囲と畳み方・案内文・.ics の予定 1 件が変わるだけ。#16・#17・#20 に反映する
- デモの流れは「開く → 今月と来月 → 下に送って 12 か月 → 一言で済み → 入園予定月で変わる → 出典 → カレンダーに入れる」になる（spec §9・demo-script.md）
- plan.md の関門 2（別の枝 6b939b2 にある）の「.ics（#20）と説明文（#19）を切る」は、この ADR に合わせて「説明文 → 起きうることの数字 の順で切り、.ics は残す」に直す。取り込みのときに行う
- 作者の n=1 の回答に基づく判断なので、11/7 の #22 で、作者の家庭の実際の入力で「開き方」をもう一度聞く。大会のあとに 3 人へ見せるときも同じ問いを入れる
