# 0007. 入院前のお金と請求の段取りを、シミュレーションから準備が進むかで優先検証する

- 状態: 置き換え（0011。未決定だった題材を確定した。検証の方法と合格条件は有効）
- 日付: 2026-11-05
- 関連: #22、[課題の比較](../problem.md)、[検証仕様](../validation/hospital-preparation.md)、[ADR 0004](0004-evidence-from-public-surveys-and-registration-first.md)、[ADR 0005](0005-twelve-month-outlook-as-main-screen.md)

## 背景

作者は4つの利用場面を見たあと、「入院前に必要なお金を確かめ、保険請求までの段取りを進める案を優先して検証していい」と答えた。

加えて、事前準備がないことと、直前まで必要額が分からないことに共通の課題があると指摘した。金額や制度を使いそうな頻度をシミュレーションできれば、対応や制度利用の準備に動けるのではないか、という仮説である。

その後に作った固定項目への入力式の試作に対し、作者は「別にテキストを項目に入力して試算したいわけじゃない」「LLMがあるのになぜアプリケーションで固定の問いに対して返答しなくてはいけないんだ」と訂正した。以下の検証は、利用者が普通の言葉で状況を話し、LLMが試算を組み立てる体験を対象にする。

これを、出来事や負担が自分の生活で具体化されていないため、準備する必要性・時期を判断できない、という仮説として検証する。公的調査だけでこの因果は確定しない。準備をしても費用負担が重い場合や、支援を利用できない場合を「本人の準備不足」と扱わない。

## 決めたこと

1. 次の作業は入院案の検証を優先する。子育て案を最終的に却下した、入院製品の本実装全体を承認した、とは扱わない。
2. 流れは **出来事を置く → 金額・時期・回数を動かす → 負担の幅を知る → 事前に確認することを選ぶ → 実際に準備する** とする。単に締切やTODOを知らせる形から、シミュレーションを入口にした形を試す。
3. 不明な金額は仮定の幅で比較できるようにする。仮定・見積もり・確認済みを区別し、仮の値を確定金額として扱わない。
4. 「利用頻度」は制度・サービスの利用回数として扱う。今回の入院試作では、退院後の追加支払いを0〜3回に変えて比べる。個人の病気・入院・再発の確率や必要な受診回数を推定しない。集団の利用実績を使うなら、対象・期間・出典を示し、個人の予測とは分ける。
5. 入口は自然な会話にする。利用者が事情・不安・手元のメモを話し、LLMが既知の条件と不明点を整理して、試算に必要な仮定と比較を提案する。初回は1件の予定入院で検証する。固定の質問票をチャット形式で順番に埋めさせることもしない。
6. 検証結果を「分かった」「準備するものを選んだ」「実際に準備が進んだ」に分ける。リンクや確認文を開いたことを、登録・請求の完了にしない。支払意思も別に確認する。
7. 質問は、その会話で結果や次の行動を大きく変える不足情報があるときに行う。「分からない」場合も仮定の幅で比較を続ける。確定できない値は確定させない。金額・日付の計算は裏側のプログラムで行い、利用者に内部の入力項目を埋める責任を負わせない。

## 検討したほかの案

| 案 | 今回採らない理由 |
| --- | --- |
| 金額・日付・回数の固定フォームを入口にする | 作者が明確に否定した。何を入力すべきか整理する負担が利用者に残る |
| 固定フォームの質問をチャットで1つずつ聞く | 入力方法が変わるだけで、文脈に応じてLLMが試算を組み立てる役割を果たさない |
| 制度の一覧と通知を先に作る | 自分に必要な準備だと実感できるか、という今回の仮説を直接試せない |
| 正確な見積もりが揃うまで計算させない | 金額が分からない段階で準備を始められるかを試せない |
| 個人の将来の疾病確率から必要額を自動で出す | 今回の根拠と範囲では個別の医療上の見通しを作れない |
| 両題材を同時に本実装する | 優先検証の選択に反し、どの仕組みが役立つか確認する前に範囲が広がる |

## 結果

現在の子育て仕様は比較・履歴として残し、作業の入口に検証仕様へのリンクを置く。子育て向けの制度データを入院データとして読み替えない。

作成済みの入力式試作は内部の計算確認用に位置づけ直す。利用者向けUIの採用案にはせず、計算テストだけを活かす。会話の例をLLM接続済みの製品として見せない。

今回の合格条件は、シミュレーションで必要額と未確認事項を説明でき、次に行う具体的な準備が決まること。実際の準備完了まで確認できて初めて行動への効果の証拠とする。作者の1件の回答だけで一般の需要や継続課金を検証済みにしない。

金額が分かっても行動が変わらない場合は、入力負担、既存の窓口で足りるか、代行や資金そのものが必要かを確かめる。入院という題材への変更だけで解決したとは判断しない。
