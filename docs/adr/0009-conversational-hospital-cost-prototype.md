# 0009. 入院前のお金の見通しを会話で試す検証用の試作を、計算の道具つきで、アプリと分けて置く

- 状態: 置き換え（0011。本体への取り込みを決めた。役割の分け方と道具の設計は有効）
- 日付: 2026-11-06
- 関連: #22、[ADR 0007](0007-test-preparation-through-hospital-cost-simulation.md)、[ADR 0008](0008-build-family-preparation-workspace.md)、[試作の README](../prototypes/hospital-conversation/README.md)、[調査メモ](../research/hospital-money-facts-20261105.md)

## 背景

ADR 0007 は、利用者が普通の言葉で状況を話し、LLM が試算を組み立てる体験を、検証の対象にした。11/5 の時点であったのは、[会話の例](../validation/hospital-conversation.md)と、内部確認用の[入力式の計算](../prototypes/hospital-preparation.html)だけで、LLM への接続は未実装だった。作者は、解き方を実際に見ないと、使う場面を想像できず判断できないと答えている。会話の例を読むだけでは、それを確かめられない。

11/6 には、同じ作業ツリーで、提出候補のアプリ（ADR 0008「家族のための準備室」）の実装が並行して進んだ。ADR 0008 は、初版に金額計算を含めないと決めている。入院費用の確認は準備の一部で、それだけで課題の全体を解いたとは扱わない、という判断である。

そこで、ADR 0007 の「金額と日付が具体的に見えれば、準備に動けるか」を実際に話して試す道具を、アプリとは別に用意するかどうかを決める必要があった。

## 決めたこと

次の形の試作を、`docs/prototypes/hospital-conversation/` に置く。**提出アプリには入れない。** 検証に使うか、アプリに取り込むかは、作者が試してから決める。

1. **役割を分ける。** Claude は、話から条件を読み取り、分からない値に仮の幅を置き、どの計算をどの筋書きで並べるかを決め、結果の意味と次に確かめることを言葉にする。金額と日付は、4 つの道具（高額療養費の上限、食事代、日付と営業日、支払いと入金を並べた見通し）だけが計算する。CLAUDE.md の「日付と金額はプログラムで計算する」を、tool use でそのまま形にした。
2. **道具は、範囲の外を断る。** 計算に使う数値（限度額の表、食事代、祝日）は、出典の URL と確認日を付けて 1 つのファイルに置く。表の期間の外、対応していない年の営業日は、計算せずに理由を返す。70 歳以上は会話で案内する計算の範囲外（計算関数自体には年齢の入力は無い）。入力は strict なスキーマで受け、さらにプログラムで確かめる。
3. **事実は、短い一覧を指示に直接入れる。** 制度と手続きの事実 16 件を、出典つきで指示に入れ、返答には番号（`[F03]`）を付けさせる。画面が番号を出典のリンクに変える。資料を検索して答える仕組みは作らない。出典の本文と突き合わせたものと、まだのものを、画面で見分けられるようにする。
4. **返答の数字を、あとから照らす。** 返答に書かれた金額と日付が、道具の入出力・利用者の発言・事実の一覧のどれかにあるかを、プログラムで検査する。見当たらないものは、返答を止めずに、注意として返答の下に出す。
5. **値の確かさを分ける。** 「確かめた額」「見積もり」「仮定」を道具の入力で区別し、確かめていない入金を手元のお金として数えない場合を、必ず並べる（ADR 0007 の 3）。
6. **Claude API は、公式の SDK で呼び、道具の往復は自前のループで回す。** 履歴は後ろに足すだけにし、system と tools はセッションの最初に決めて変えない（Claude Opus 5.5 / Sonnet 5.5 の思考ブロックは、それより前が変わると使えなくなるため）。拒否・未完の道具呼び出し・文章なしで終わった往復は履歴に入れない。文章だけが途中で切れた場合は、注意とともに残して続けられるようにする。変わらない部分はプロンプトキャッシュに乗せる。既定のモデルは `claude-opus-5-5` だが、このリポジトリでは `.env.local` の `ANTHROPIC_MODEL`（`claude-sonnet-5-5`）に合わせる。ベータの機能（拒否されたときのサーバー側のフォールバック、思考ブロックの扱いの指定）は、API が受け付けなければ使わない形に切り替えて続ける。
7. **データは、この端末の中に留める。** サーバーは `127.0.0.1` だけで待ち受け、Host と Origin を確かめる。会話はメモリの中だけに置き、ファイルにもブラウザにも保存しない。ログに本文と鍵を出さない。利用者の文章が Anthropic の API へ送られることは、画面に書く。
8. **しないこと。** 医療の助言と確率、給付の可否と額の判断、商品のすすめ、連絡や申請の代行（ADR 0007、大会の「作らないもの」）。

## 検討したほかの案

| 案                                                      | 採らなかった理由                                                                                                                                    |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 提出アプリ（Next.js）に、いま組み込む                   | ADR 0008 が、初版から金額計算を外している。並行して動いている実装のファイルに手を入れることにもなる。取り込むかは、作者が両方を触ってから決められる |
| 金額と日付も Claude に計算させ、あとで検算する          | CLAUDE.md の決まりに反する。検算で直せるのは、見つけられた誤りだけ                                                                                  |
| 見当たらない数字があったら、返答を出さない              | 言い換えや丸めでの誤検出で、会話が止まる。検証用なので、止めずに注意を出し、どれだけ起きるかを見る                                                  |
| SDK のツールランナーに、道具の往復を任せる              | 拒否・途中で切れた応答・道具の失敗の扱いを、API を呼ばないテストで確かめたい。画面と検査に、道具の入出力をそのまま渡したい                          |
| SDK を使わず、`fetch` で API を呼ぶ                     | 再試行、エラーの型、ベータの指定を、自前で作り直す理由がない                                                                                        |
| 返答と表を、構造化出力で 1 回で作る（アプリと同じ方式） | 条件が変わるたびに、計算をやり直す往復が要る。計算を道具に分けるほうが、「プログラムが計算した数字だけを見せる」を守りやすい                        |
| 制度の資料を検索して答える                              | 大会の「作らないもの」に当たる。事実は 16 件で、指示にそのまま入る                                                                                  |
| 固定の入力項目、決まった順の質問                        | ADR 0007 で作者が否定した                                                                                                                           |

## 結果

良くなること:

- 作者が、自分の言葉で話して、使う場面を想像できるかを確かめられる。ADR 0007 の合格条件（必要額と未確認事項を説明でき、次の準備が決まる）を、会話の例ではなく実物で試せる。
- 計算は、API を呼ばずにテストと CLI で確かめられる。アプリに取り込むことになっても、計算と道具の定義はそのまま使える。

引き受けること:

- 起動のしかたと Claude の呼び方が、アプリ（AI SDK・構造化出力）と試作（公式の SDK・tool use）の 2 通りになる。提出物でどちらを見せるかは、別に決める必要がある。
- 計算の範囲は狭い（協会けんぽ・70 歳未満・1 か月・1 つの医療機関）。国民健康保険の人には、区分の決まり方が違うと伝えるだけになる。
- 返答の検査には、見逃しと誤検出がある。実際の API での確認では、丸めた額（「5 万円ほど」）を指摘できた一方で、道具の結果の説明文にある額（区分の条件の「28 万〜50 万円」）を誤って指摘した（後者は直した）。
- 事実の一覧は、人が出典を開いて確かめ続ける必要がある。制度の改定（限度額の表は 2027 年 8 月に切り替わる）のたびに、数値のファイルを直す。

見直す条件:

- 作者が試して、使う場面を想像できない・準備に動く気にならないと答えたら、検証の記録として残し、ここで止める。動くことを、役に立つことの証拠にしない。
- アプリに金額の見通しを入れると決めたら、`src/` の計算と道具をアプリ側へ移し、この ADR を置き換える。

確かめたことと、確かめていないことは、[試作の README](../prototypes/hospital-conversation/README.md) と[ワークログ](../worklog/20261106.md)に書いた。
