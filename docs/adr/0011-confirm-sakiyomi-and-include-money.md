# 0011. 発表する製品を「さきよみ」に確定し、入院前のお金の計算を本体に入れる

- 状態: 採用
- 日付: 2026-11-06
- 関連: #29、#27、#28、[ADR 0007](0007-test-preparation-through-hospital-cost-simulation.md)、[ADR 0008](0008-build-family-preparation-workspace.md)、[ADR 0009](0009-conversational-hospital-cost-prototype.md)、[ADR 0012](0012-open-production-with-usage-limits.md)

## 背景

11/6 の昼の時点で、リポジトリには案が 3 つ別々にあった。

| 案                                         | そのときの状態                                                           |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| 子育ての見通し（ADR 0002〜0006）           | 仕様と制度データだけ。アプリのコードは無い                               |
| さきよみ「家族のための準備室」（ADR 0008） | Next.js で動き、Vercel に配置済み。金額は計算しない                      |
| 入院前のお金の見通し（ADR 0009）           | `docs/prototypes/hospital-conversation/` の試作。テスト 131 件。本体と別 |

提出は 11/8 20:00 で、動画も概要も、製品を 1 つに決めないと書けない。ADR 0007 は「製品の題材変更は未決定」、ADR 0009 は「取り込むかは作者が試してから」のままだった。

子育て案から離れた経緯は次のとおり。11/4 の紙の試作に、作者自身が「この形では自分の家庭では使わないと思う」と答えた（ワークログ 11/4、ADR 0006）。11/5 に子育てと入院の場面を 2 つずつ比べ、作者は入院案の優先検証を選び、固定の入力欄を否定した（ADR 0007）。

作者は 11/6 に、発表する製品をさきよみに決め、お金の計算を本体に入れると決めた。

## 決めたこと

1. **発表する製品は「さきよみ — 家族のための準備室」にする。** 子育て案は発表しない。仕様と制度データは経緯として残す。
2. **テーマは 2「本来、誰にでも届くべきものを」にする。** 越える壁は専門知識と手続き。高額療養費が月ごとに計算されることや、窓口で上限を使うための条件を知らないと、退院の日にいくら要るかを自分で計算できない。
3. **金額の計算を本体に入れる。** 範囲は試作と同じ 4 つ（高額療養費の上限、食事代、日付と営業日、手元資金の見通し）。作者の指示どおり、計算は試作から本体へ移す（#27）。
4. **Claude は条件の読み取りと説明を受け持ち、金額と日付はプログラムが計算する。** 返答に書かれた金額と日付は、計算の入出力・利用者の発言・出典つきの事実と照らす。
5. **お金だけの製品にはしない。** 暮らしの引き継ぎ、確かめる・頼む文、残しておく言葉はそのまま残す。ADR 0008 の「入院費用の確認は準備の一部」という見方は変えない。足りない額が分かっても、アプリが現金を用意できるわけではないからである。
6. **作者の体験は、提出文書で一文だけ触れる。** 病名・経緯・家族の詳細は書かない。デモと評価の入力には、架空の人物と金額だけを使う。
7. **公開のしかたは ADR 0012 で決める。** ここでは決めない。
8. **しないことは変えない。** 医療と心理の助言、給付の可否と額の判断、保険商品のすすめ、連絡や申請の代行はしない。大会の「作らないもの」にも当たる。

## 置き換える判断

古い ADR は消さず、状態を「置き換え（0011）」にする。

| ADR        | 置き換える部分                                                  | 残すもの                                                   |
| ---------- | --------------------------------------------------------------- | ---------------------------------------------------------- |
| 0002〜0006 | 製品の題材としての役割（子育ての見通し、12 か月の画面、第一声） | 既存のアプリと競合の調べ方、公的調査を読む手順の記録       |
| 0007       | 「提出する製品の題材変更は未決定」                              | 検証の方法。準備が実際に進むかを分けて確かめる合格条件     |
| 0008       | 「初版に金額計算を含めない」                                    | 会話を入口にすること、カードの保護、持ち出しの範囲         |
| 0009       | 状態「提案」と「提出アプリには入れない」                        | 役割の分け方、道具の設計、確かめたことと確かめていないこと |

## 検討したほかの案

| 案                                       | 採らなかった理由                                                                                                                                                                                     |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 子育て案を発表する                       | 作者自身が紙の試作に「この形では使わない」と答えた。アプリのコードも無かった                                                                                                                         |
| ADR 0008 のまま、金額を含めない          | 「いくら要るのか」という最初の問いに答えられない。確認文を作るだけでは、何を確かめると見通しが変わるのかも示せない                                                                                   |
| お金の見通しだけを製品にする             | 「誰に何を頼むか」が落ちる。足りない額が分かっても、アプリは現金を用意できない（[課題の比較](../problem.md)）。そのあとに残る手は、確かめることと頼むことである                                      |
| 試作を本体と別のアプリのまま並べて見せる | 3 分の動画で 2 つのアプリを説明できない。起動のしかたも 2 通りになる（ADR 0009 の「引き受けること」）                                                                                                |
| 金額も Claude に計算させ、あとで検算する | 検算で直せるのは見つけられた誤りだけ。試作の実 API の確認では、モデルが丸めた額（「5 万円ほど」）、自分で足した小計、道具を通していない日付が実際に出た（[ワークログ 11/6](../worklog/20261106.md)） |

## 結果

良くなること:

- 動画と文書で見せる製品が 1 つになる。「1 週間延びたら」と話すと、同じ会話の中で金額が変わり、同じ画面で引き継ぎのメモも選んで渡せる。
- 金額と日付の誤りを、プログラムのテストで確かめられる。

引き受けること:

- **効果は確かめていない。** 当事者の評価は未実施で、11/8 までに間に合うとは限らない。動くことを、役に立つことの証拠にしない（ADR 0007）。
- 計算の範囲が狭い。協会けんぽ・70 歳未満・1 か月・1 つの医療機関の入院の保険診療分だけで、国民健康保険などは区分の決まり方が違うと伝えるところまでになる。
- 限度額の表は 2027 年 7 月診療分までで、2027 年 8 月に区分が変わる。続けるなら表の更新が要る。
- 題材を 11/6 に確定したので、本体のコードは若い。仕様の聞き取りと制度データの多くは子育て案に使った作業で、製品には入っていない。提出文書ではこれを隠さない。
- 子育て案の Issue は、題材変更の理由を書いて閉じる（#29）。

見直す条件: 当事者が試して、金額が分かっても確認や依頼に動かないと分かったら、入力の負担、既存の窓口で足りるか、代行や資金そのものが要るのかを確かめ直す。
