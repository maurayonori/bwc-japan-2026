# 0012. 本番 URL を利用上限つきで公開し、Vercel ログインを外す

- 状態: 採用（ADR 0010 の「全 URL を認証で保護する」を置き換える）
- 日付: 2026-11-06
- 関連: #28、[ADR 0010](0010-host-on-vercel-with-authentication.md)、[ADR 0011](0011-confirm-sakiyomi-and-include-money.md)

## 背景

本番 URL は Vercel ログインが必要で、審査員も、困っている当事者も触れなかった。提出要件は動画とリポジトリなので公開は必須ではないが、作者は「触れること」を選んだ。ログインを外すと、誰でも作者の API キーで Claude を呼べる。費用と悪用への備えが要る。

## 決めたこと

1. 本番の固定 URL だけを公開する。個別デプロイの URL とプレビューは、これまでどおり Vercel ログインで保護する（`prod_deployment_urls_and_all_previews`）。
2. 架空の体験例は回数の制限なく試せる。API を呼ばない。
3. Claude との会話は 3 段で制限する。
   - **端末ごと**: 1 日 20 回（`LIMIT_PER_CLIENT_PER_DAY`）
   - **全体**: 1 日 150 回（`LIMIT_GLOBAL_PER_DAY`）
   - **短時間の連打**: Vercel Firewall のルールで、`/api/chat` への送信を IP ごとに 1 時間 20 回まで
4. 端末の見分けには、接続元を起動ごとの乱数と混ぜた要約だけを使い、接続元そのものを保存しない。IPv6 は /64 を 1 つの接続元として数える。数は日本時間の 0 時で切り替わる。
   1 回の入力が大きいほど費用が増えるので、本文は 60,000 バイトまでとする（道具の往復ごとに送り直すため）。メモがすでに 24 件あるときは、回数を減らさず、Claude を呼ぶ前に断る。
5. 上限に達したら HTTP 429 と案内を返す。入力とメモは画面に残す。API の失敗を見本の回答ですり替えない方針（ADR 0008）は変えない。
6. 公開版である旨と、実名や病名を書かず架空の内容で試してほしい旨を、入力欄の近くに表示する。検索エンジンには載せない（`X-Robots-Tag: noindex`）。

配置の順序は、上限のコードとルールを先に入れて確かめてから、ログインを外す。

## 検討したほかの案

| 案                                               | 採らなかった理由                                                                                          |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| ログインのまま、動画とコードだけで審査してもらう | 費用の心配は無いが、作者が公開を選んだ。当事者に試してもらう道も無くなる                                  |
| 体験例だけを公開し、会話は合言葉で開ける         | 提出フォームの文面に合言葉を置く必要がある。審査員の手間が増え、漏れたら結局上限が要る                    |
| Redis などで厳密に数える                         | 外部サービスの契約と鍵が増える。提出まで 2 日で、体験に効かない                                           |
| 利用者が自分の API キーを入れる                  | 「専門知識の壁で助けを受けられない人に届ける」というテーマに反する。困っている人は API キーを持っていない |

## 結果

良くなること: 審査員と当事者が、ログインもキーも無しで、自分の言葉で試せる。

引き受けること:

- **端末ごと・全体の回数はメモリの中で数えるので、厳密な上限ではない。** 実行インスタンスが増えるとその数だけ緩み、入れ替わると数え直しになる。Firewall のルールは複数のインスタンスをまたいで効くが、時間あたりの制限で、1 日の総量は押さえない。
- API の残高が尽きると会話は失敗する。アプリは失敗を案内するだけで、体験例は動き続ける。残高はこのアプリからは見えないので、提出前と審査の前に Anthropic のコンソールで確かめる。
- 利用者が入力した内容はサーバーを経由して Anthropic へ送られる。アプリは保存もログ出力もしない。

見直す条件: 審査のあと（11/10 以降）に、ログインへ戻すか、上限と運用を設計し直すかを決める。API キーの費用を作者が払い続ける形のまま、広く使ってもらう想定にはしない。
