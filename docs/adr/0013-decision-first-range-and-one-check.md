# 0013. 主役を「退院の日に要る額の幅」と「まず確かめる 1 つ」にし、メモは渡すものとして下に置く

- 状態: 一部置き換え（0016。見通しの先頭に、窓口で上限を使う場合と使わない場合の支払日の額を置く。順位と確認 1 つは変えない）
- 日付: 2026-11-07
- 関連: #30、[ADR 0011](0011-confirm-sakiyomi-and-include-money.md)、[ADR 0007](0007-test-preparation-through-hospital-cost-simulation.md)、[ADR 0008](0008-build-family-preparation-workspace.md)、[現在の仕様](../family-preparation.md)、[調査メモ](../research/hospital-money-facts-20261105.md)

## 背景

作者の判断は「ただのメモアプリに見える。課題を解決しつつ勝てる内容ではない」だった。

11/7 昼の main（`3bd2927`）の本体は、次のとおりだった。

- **4 種のカードが同じ重さで並ぶ。** 種類は `lib/workspace.ts` の `kinds` にあり、01 暮らしの引き継ぎ、02 確かめる・頼む、03 残しておく言葉、04 お金の見通しの順。`app/workspace.tsx` の「家族のしおり」は、カードを作られた順に同じ形で並べ、絞り込みは「すべて」と 4 種のボタンを横に並べる。上には「n / m 件の準備ができました」と件数を出す。カードが無いときの案内も「退院の日に要るお金。朝の支度の引き継ぎ。窓口への質問文。大切にしておきたい、今日のひと言。」と 4 つを並べる。お金の見通しは 4 種の最後の 1 つだった。
- **何を確かめると見通しが変わるかの順位が、文章に埋もれていた。** `lib/prompt.ts` は「幅を狭めるために誰に何を聞けばよいかを、その人の状況に合わせて提案する。先に挙げるのは、結果を一番大きく動かす不明点」と指示し、お金のカードの本文に「その幅を生んでいる条件を3つまで」書かせる。どれが一番大きく動かすかはモデルが文章の中で決めており、プログラムは計算していない。画面に数字で出る幅は、所得区分が分からないときの幅（`range_if_category_unknown`）だけだった。
- **窓口への質問文は、お金の幅とつながっていない。** 質問文は「確かめる・頼む」の別のカードになり、それを確かめると幅がいくら縮むかは示していない。

ADR 0011 で選んだテーマの壁は「制度を知らないと、退院の日にいくら要るかを自分で計算できない」ことだった。今の画面は、計算の結果を 4 つのメモの 1 つとして見せ、次に何を確かめれば見通しが定まるかを示していない。

## 決めたこと

1. **画面の最上段には 2 つだけを置く。** 「退院の日に要る額の幅」（下限〜上限）と、「その幅をいちばん縮める確認 1 つ」（誰に、何を聞くか）。お金の表、計算の記録、暮らしの引き継ぎ、確かめる・頼む、残しておく言葉は、その下に「渡すもの」として置く。
2. **不明点の列挙と順位はプログラムが決める。** 不明点は 3 種類ある。どの筋書きになるか（筋書きが 2 本以上のとき）、確かめていない入金が入るか（入らない場合を必ず含める）、確かめていない支払いのうち下限と上限が違うものの額。同じ向き・同じ名前の入出金は、筋書きをまたいでも 1 つの不明点にまとめる。「確かめた」の額は数えない。入出金の不明点は幅の大きいものから 6 つまでを比べ、比べなかった数も結果に書く。不明点の名前もプログラムが作る。Claude が受け持つのは、話から条件と仮の幅を読み取ることと、先頭の不明点を誰に、何を、どう聞くかを書くこと。Claude に順位を決めさせない。
3. **順位は「確かめたとき、答えがどちらでも残る幅」で決める。** 幅（`width`）は、退院の日に要る額（`need`。その日までの支払いをまかなうために手元に要る額）の、すべての筋書きと答えの組み合わせのうち最大と最小の差。不明点ごとに、答え（支払いは少なめ・多め、入金は入らない・入る、筋書きはそれぞれ）ごとの幅を計算し、大きい方を `width_if_resolved`（確かめても残る幅）、`width` との差を `shrink`（縮む額）とする。`shrink` の大きい順に並べ、先頭を「まず確かめる 1 つ」にする。同じ値なら、筋書き → 入金 → 支払いの額 → 入力に出てきた順に並べ、実行ごとに変えない。
4. **順位は `simulate_cashflow` の結果に同梱する。** 結果の `what_to_confirm` に入れる（実装は `lib/money/confirm.ts`、#31）。入力が同じなので、新しい道具を足さない。Claude が呼ぶ回数も増えない。順位だけを返す第 5 の道具は、手元資金の見通しの外にある不明点まで比べたくなったときの、将来の拡張とする。
5. **幅は置いた仮定の下限と上限で、確率ではない。** 「起こりやすさ」や信頼区間として書かない。入院日数などに置いた仮の幅は、利用者が言った値か仮に置いた値で、医学的な見通しではない。
6. **答えを話すと「仮定」が「確かめた」に変わり、幅が縮む。** 利用者が窓口で聞いた答えを話すと、その値の確かさを「確かめた」にして計算し直し、縮む前と後の幅を並べる。まだ縮められる不明点があれば、次の 1 つを出す。
7. **計算の記録は隠さない。** 順位の根拠（今の幅、確かめても残る幅、縮む額）と、道具に渡した値とその確かさを、開けば読めるようにする。
8. **ADR 0011 の「お金だけの製品にしない」は、主従を変える形で守る。** 3 種のメモは消さず、主役の下に、家族や窓口へ渡すものとして置く。足りない額が分かってもアプリは現金を用意できない、という ADR 0011 の理由は変わらない。
9. **変えないもの。** 計算の範囲（協会けんぽ、70 歳未満、1 か月・1 つの医療機関の入院の保険診療分など）、データの範囲、しないこと。金額と日付はプログラムが計算する。給付の可否・額・時期を断定しない。
10. **一文と副題は候補として置き、作者が最後に決める。** 製品名「さきよみ」は変えない。

## 検討したほかの案

| 案                                        | 採らなかった理由                                                                                                                                                                                                                             |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 今のまま、4 種のカードを並べる            | 作者の判断は「ただのメモアプリに見える」。何を確かめると見通しが変わるかが文章の中にあり、比べられない                                                                                                                                       |
| 順位も Claude に任せ、文章で示す          | 順位は金額の差から決まる。金額を Claude に計算させないのと同じ理由で、順位も検算できるプログラムに置く。モデルに任せると、同じ入力で順位が変わりうる                                                                                         |
| 確率やモンテカルロで、要る額の分布を出す  | 仮の値に分布の根拠が無い。入院日数などに分布を置くと、医学的な見通しを言うことになり「しないこと」に当たる。幅を「確からしさ」と読ませてしまう                                                                                               |
| お金だけの製品にする                      | ADR 0011 で採らなかった理由が残る。足りない額が分かっても、アプリは現金を用意できない。そのあとに残る手は、確かめることと頼むことである                                                                                                      |
| 病院の窓口や相談員が使う B2B の画面にする | 入口が当事者の自由な会話でなくなり、題材から外れる。病院には入院前の支援に入院時支援加算の点数があるが（[調査メモ](../research/hospital-money-facts-20261105.md)）、その業務とどう重なるかは確かめていない。提出までに導入先の検証もできない |
| 順位だけを返す第 5 の道具を足す           | 入力が `simulate_cashflow` と同じで、呼ぶ回数が増えると応答の打ち切り（52 秒）に近づく。Claude が呼び忘れると順位が出ない。手元資金の見通しの外の不明点を比べるときの、将来の拡張に残す                                                      |

## 結果

良くなること:

- 開いた人が最初に見るのが、「いくら要るか（幅）」と「まず何を確かめるか」になる。
- 順位がプログラムの計算になり、テストで確かめられる。根拠（縮む額）も画面で読める。
- 答えを話すと幅が縮むので、確かめることの意味が数字で見える。

引き受けること:

- **提出の約 24 時間前に、本体の主画面が変わる。** 実装は別のセッションで進め、11/7 に main へ入った（#31〜#34）。録画済みの動画、提出文、README は前の画面のままなので、実機の数字が出てから書き直す（この ADR の範囲外）。
- **順位の指標は「幅の縮み」1 つだけ。** 確かめる手間、窓口が開いている日、聞きにくさは数えない。縮む額が小さくても、すぐ聞ける確認を先にしたい人には合わない。
- **比べる入出金の不明点は 6 つまで。** 組み合わせの数を抑えるためで、7 つ目からは順位に入らない（入らなかった数は結果に出す）。
- **当事者の評価は 0 件。** 幅と確認 1 つを見て、人が実際に窓口へ聞きに行くかは確かめていない。動くことを、役に立つことの証拠にしない（ADR 0007）。
- 幅は、利用者が話した値と仮に置いた値の範囲でしか縮まない。話されていない費用（差額ベッド代など）は、幅の外に残る。

見直す条件: 当事者が幅と確認 1 つを見ても窓口に聞きに行かなければ、順位の定義（幅の縮みだけでよいか）と、話すことの負担を見直す。
