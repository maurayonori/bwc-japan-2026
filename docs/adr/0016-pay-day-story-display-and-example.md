# 0016. 支払日に要るお金を見通しの先頭に並べ、架空の体験例を動画と同じ条件にし、副題を「入院のお金、支払日に間に合う準備」にする

- 状態: 採用
- 日付: 2026-11-07
- 関連: #55、#38、#37、[ADR 0013](0013-decision-first-range-and-one-check.md)、[ADR 0015](0015-one-menu-for-sakiyomi-roadmap-and-play.md)、[現在の仕様](../family-preparation.md)、[調査メモ](../research/hospital-money-facts-20261105.md)

## 背景

11/7 の夜、提出の約 20 時間前に、作者が大会用のストーリーを 1 本に整理した。軸は「制度利用の確認と手続きで、避けられる一時立替と資金不足を減らす」。

ADR 0013 で主役は「退院の日に要る額の幅」と「まず確かめる 1 つ」になり、実装は 11/7 の昼に main へ入った（#31〜#34、#44）。しかし、この軸に照らすと、画面と文書には次の隙間があった。

- 幅は「下限〜上限」の 1 つの数字で出ていて、「窓口で上限が使える場合」と「使えずにいったん 3 割を払う場合」の 2 つの額が並んで見えない。差（避けられる一時立替）と、手元のお金との差（資金不足）が、計算の記録を開かないと読めない
- 架空の体験例は 11 月の 15 日間・窓口負担 24 万〜30 万円・手元のお金は不明という条件で、動画（12 月 14 日〜28 日、総額 80 万円、手元 20 万円）と違っていた。README の表は「60 万・20 万」の行を使い、提出文は動画の値を使っていて、3 つが揃っていなかった
- 副題は「家族のための準備室」のままで、ADR 0013 は候補を置いて作者の判断を待っていた

## 決めたこと

1. **表示の層だけを変える。** 触るのは `app/money-card.tsx`（`PayDayBlock` と `ConfirmBlock`）、`app/money.css`、`app/workspace.tsx` の最初の一言と見出し、`app/site-header.tsx` と `app/layout.tsx` の副題、`lib/money/format.ts` の表示の部品、`lib/example.ts`。`lib/money/`（計算・順位・検査）、`lib/prompt.ts`、`lib/chat.ts`、`app/api/` は触らない。動画に映る既存の文言も変えない。
2. **「見通し」の先頭に「支払日に要るお金」の表を置く。** 列は、筋書き、要る額、いつ、手元のお金との差、確かさ。確かさは、その筋書きの支払いに含まれる確かさを「確かめた額・見積もり・仮定」の順に並べて書く（食事代が見積もりなら、入院費を確かめても「確かめた額・見積もり」になる）。筋書きが 2 つ以上のときは、先頭の筋書きとの差（上限が使えないときにいったん立て替える額）と、払い戻しは診療月から 3 か月以上あとという注意を出す。注意は [F05]（協会けんぽの案内、確認 2026-11-06）の出典つきで、出典の一覧にも入れる。値はすべて `simulate_cashflow` の結果で、画面で新しい数字を作らない。
3. **その下に「まず確かめる 1 つ」、さらに下に計算の記録を置く。** 幅、確かめると残る幅、答えごとの要る額、聞く相手と質問文のコピー。順位はプログラム（ADR 0013）のまま。
4. **架空の体験例を動画と同じ条件にする。** 2026 年 12 月 14 日〜28 日の 15 日間、協会けんぽ、区分ウ、医療費の総額 80 万円、手元 20 万円。返答は 2 回で、1 回目は上限が使える場合と使えない場合を並べて「まず確かめる 1 つ＝窓口で上限が使えるか（病院の会計）」を出し、2 回目は「病院に聞いたら、マイナ保険証で窓口の上限は使えると言われました」を受けて筋書きが 1 本になり、要る額が 1 つになる。病院の答えで確かめたのは「窓口で上限が使えるか」だけで、医療費の総額 80 万円（病院の見積もり）と食事代は見積もりのまま（2026-11-08 訂正。当初は「額が『確かめた額』に決まる」と書いていたが、確かめたのは条件で、額ではない。#62）。数字は手で書かず、本番と同じ計算関数で作る（`exampleMoneyTurns`）。文章の数字もその結果を埋める。
5. **副題は「入院のお金、支払日に間に合う準備」にする。** 作者が提出の前に別の語に変えるなら、`app/site-header.tsx`・`app/layout.tsx`・README・提出フォームの 4 か所を揃えて変える。 画面のヘッダー、`<title>`、README の題、提出フォームのプロジェクト名を揃える。「家族のための準備室」は節名には使わず、「渡すもの」の説明で「家族と窓口に渡すもの」として残す。
6. **最初の一言は、話してほしいことと、返ってくるものを 1 文ずつにする。** 「入院の予定と、分かっている金額や手元のお金を、そのまま話してください。支払日に要るお金を、窓口で上限が使える場合と使えない場合で並べ、まず確かめる 1 つを出します。家族に頼みたいことも、思いついた順で。」固定の質問票にはしない。
7. **一文は次のとおり。** 「入院が決まった人が普通の言葉で話すと、支払日に要るお金を、窓口で上限が使える場合と使えない場合で並べ、まず確かめる 1 つを出す Web アプリです。家族や窓口に渡す文章も Claude が下書きします。」
8. **README と提出文の金額は、計算関数と照合するテストを置く。** `tests/readme-numbers.test.ts` が README の表の 5 行（1 回目の 2 行と、月をまたぐ 3 行）と提出文の段落を、`kougakuGendo`・`mealCost`・`simulateCashflow` の結果と `yen()` の文字列で突き合わせる。月をまたぐ行は、診療月を 2026-12 と 2027-01 に分けて計算する（上限は月ごと）。2026-11-08 に、照合の範囲を仕様（`docs/family-preparation.md`）とこの ADR の体験例の条件まで広げた（#62）。

## 検討したほかの案

| 案                                                 | 採らなかった理由                                                                                                                                                                                      |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2 つの額の差や手元との差を、Claude に文章で書かせる | 金額を Claude に生成させないという決まりに反する。差は `comparison_with_first` と `cash_on_hand` から表示の層で組み立てられる                                                                         |
| 体験例を 1 回目の返答で止める                       | 「答えを話すと筋書きが 1 本になり、幅が無くなる」という、確かめることの意味が数字で見える場面が無くなる。動画も 2 回目まで映す                                                                                 |
| 副題を「家族のための準備室」のまま残す              | 作者の軸は支払日のお金で、副題がそれを言っていない。渡すものは残るので、説明の中で「家族と窓口に渡すもの」として残せば足りる                                                                         |
| 計算の層に「支払日」の概念を足す                   | `simulate_cashflow` の `need_date`（一番きつくなる日）がすでにその日を返す。提出の前夜に `lib/money/` を触ると、検査と順位づけのテストを全部見直すことになる                                           |
| README の表に「60 万・20 万」の行を残す            | 動画と提出文は「80 万がすべて 12 月」を下限にしている。前提の違う行が 3 か所に散ると、読む人が数字を突き合わせられない                                                                                 |

## 結果

良くなること:

- 開いた人が最初に見るのが、支払日に要るお金の 2 つの額、その差、手元のお金との差になる。避けられる一時立替と資金不足が、数字で読める
- 体験例・動画・README・提出文の数字が同じ条件になり、テストで照合できる
- 副題と最初の一言が、作者の軸と同じことを言う

引き受けること:

- **動画の録り直し。** 画面と体験例が変わったので、v1（https://youtu.be/c-3mh5sisec）は前の画面のまま。v2 を 11/8 午前に録り直して差し替える
- **文書の書き換え。** README、仕様、提出文、CLAUDE.md、ADR の一覧をこの判断に合わせる（#38、#55）
- **当事者の評価は 0 件のまま。** 支払日の表と確認 1 つを見て、人が窓口へ聞きに行くかは確かめていない。効果は未評価と書き続ける
- 月の内訳（費用が 12 月に寄るか半々か）は Claude が仮に置くので、実際の返答が README の表と同じ値になるとは限らない。表には、その旨を書く

見直す条件: 当事者が支払日の表を見ても窓口に聞きに行かなければ、見せる順（額が先か、確認が先か）と、表の列を見直す。2027 年 8 月の区分の細分化で表を更新するときは、体験例の条件（区分ウ、総額 80 万円）も見直す。
