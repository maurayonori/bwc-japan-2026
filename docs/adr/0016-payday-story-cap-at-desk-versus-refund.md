# 0016. 大会のストーリーを「使える制度を、支払日に間に合う準備へ」にし、窓口で上限を使う場合と使わない場合の支払日の額を先頭に並べる

- 状態: 提案（PR のマージで採用。マージと本番への配置は、統括が手元で実 API を使って確かめてから行う）
- 日付: 2026-11-07
- 関連: #55、#38、#3、#4、#37、[ADR 0011](0011-confirm-sakiyomi-and-include-money.md)、[ADR 0013](0013-decision-first-range-and-one-check.md)、[ADR 0015](0015-one-menu-for-sakiyomi-roadmap-and-play.md)、[現在の仕様](../family-preparation.md)

## 背景

作者の判断は「体験として散らかりすぎている」だった。作者は別のエージェントと、大会で伝わる一本のストーリーを整理した。軸は「制度利用の確認と手続きで、避けられる一時立替と資金不足を減らす」。

- 対象: 入院が決まり、まとまった立替が家計の負担になる本人と家族。特に、窓口で医療費の上限を使えるかをまだ確かめていない人
- できること: 高額療養費には、あとで払い戻しを受ける方法と、窓口での支払いを上限までに抑える方法がある。自分の場合の差額を計算し、病院への確認と必要な準備につなげる
- 一巡: アプリが担うのは計算、質問文、準備の支援、回答後の更新。本人が窓口で確認と手続きを進め、適用につながるところまで

11/7 夕方の main（`b647a50`）は、次のとおりだった。

- 最初の画面の副題は「家族のための準備室」、最初の一言は「入院のことや家族に頼みたいことを、思いついた順にそのまま話してください。」で、お金の話か家族の話かが定まらない
- 見通しの先頭は ADR 0013 の「要る額の幅」と「まず確かめる 1 つ」。窓口で上限を使う場合と使わない場合の額は、確認 1 つの答えの表（要る額）と、下の資金繰りの表に分かれていた。2 つの差（避けられる一時立替）と、手元のお金と比べた結果は、どこにも並んでいなかった
- 架空の体験例は 11 月・入院費の概算 24 万〜30 万円・手元のお金は話していない例で、ストーリーの例（12 月・総額 80 万円・手元 20 万円）と数字が違った
- README と提出文は、4 種のカードを同じ重さで並べていた

## 決めたこと

1. **軸と一文はストーリーのものにする。** 一文は「入院が決まった人に、還付を待つ間のお金まで用意する負担が生じることがあります。さきよみは、普通の言葉から支払いの見通しを計算し、使える制度の確認と必要な手続きにつなげます。」と「使える制度を、支払日に間に合う準備へつなぐアプリです。」。製品名「さきよみ — 家族のための準備室」と提出フォームのプロジェクト名は変えない（作者が決める）。
2. **最初の画面の副題を「使える制度を、支払日に間に合う準備へ」にする。** `app/site-header.tsx` の文字列だけを変え、ヘッダーとメニューの構成は変えない。最初の一言は「入院の予定や医療費の見込みを、そのまま話してください。支払日に要るお金をプログラムが計算し、使える制度の確認と準備を整理します。医療や給付の判断はしません。」にする。医療の助言の道具に見えないよう、長い免責文を足さずに一言に含める（PdM の依頼、外部レビューの指摘）。会話が主役の画面はそのまま。
3. **お金のカードの先頭と、最新の返答の下に「支払日に要るお金」を出す。** 「窓口で上限を使う」と「使わずに、あとで還付」を横に並べ（狭い幅では縦）、それぞれの支払日に要るお金、手元のお金と比べて残る額か足りない額、内訳の確かさ（確かめた額・見積もり・仮定）を出す。下に差（避けられる一時立替）と、還付の時期（F05）・窓口で上限を使う方法（F02）を、出典のリンクと確認日つきで添える。返答の下には、内訳と出典を省いた短い版を置く。
4. **どちらの筋書きかは、プログラムが計算の額で見分ける。** `lib/views.ts` の `paydayOf` は、見通し（`simulate_cashflow`）の筋書きの支払いの行が、高額療養費の計算（`kougaku_gendo`）の `pay_with_cap` と一致するか、`copay_without_cap` と一致するかで「上限を使う」「使わない」を決める。少なめと多めの両方の額が一致する行だけを数える。Claude が付けた筋書きの名前では決めない。
5. **金額は計算の出力から選んで並べるだけにし、画面で新しい額を作らない。** 要る額は `need`、足りない額は `shortfall`、残る額は手元のお金と各行の残り（`balance`）のうち一番小さい値、差は `comparison_with_first`（一番上の筋書きとの差。向きだけそろえる）、立て替える額は `refund_later`。差が `refund_later` と同じときだけ「避けられる一時立替」と呼び、違うときは「支払日に要るお金の差」と呼ぶ。
6. **見分けられないときは出さない。** 区分が分からず 5 区分を並べた計算、上限で窓口負担が減らない額、同じ側の筋書きが 2 本以上ある見通し（月をまたぐときの内訳の違いなど）、高額療養費の計算が無い見通し。そのときは今までどおり、ADR 0013 の幅と確認 1 つが先頭になる。
7. **病院の答えのあと（上限を使う筋書きだけが残ったとき）は、片側だけを出す。** 使わない側は「この見通しには入れていません」とし、高額療養費の計算から、上限が無いときの窓口負担と、還付まで立て替える額を添える。どちらも 1 か月・1 区分の計算のときだけ出す。
8. **ADR 0013 の順位と「まず確かめる 1 つ」は変えない。** 支払日の欄の下に置く。不明点の列挙と順位はプログラム、質問文は Claude のまま。確かめることが残っていない（幅が 0）ときは、返答の下のリンクに「まず確かめる 1 つ」と書かない。
9. **架空の体験例をストーリーの例にし、2 段にする。** 最初は病院に聞く前（2026 年 12 月 14〜28 日、協会けんぽ、給料から区分ウと仮定、総額 80 万円、手元 20 万円、食事代は 1 日 3 食の仮定、支払いは退院の日の仮定）。例の帯の「続き: 病院の答えを話す」で、病院の答え（「病院に聞いたら、マイナ保険証で窓口の上限は効くと言われました。」）を話したあとの返答を重ねる。重ねるのは画面の会話と同じ `mergeCards` で、直したカードは上書きしない。お金のカードが守られているときは、本番（`lib/money/attach.ts`）と同じく別の番号の新しいカードにする。入院費の額は見積もりの総額からの計算なので、答えのあとも確かさは「見積もり」のまま。数字はすべて本番と同じ計算関数で作る。
10. **前の体験例は、テスト用の固定データとして残す。** 幅の縮み方、質問文の選び方、持ち出し、検査のテストは、入院費に幅がある前の体験例（`tests/fixtures/range-example.ts`）で、同じ数字のまま確かめ続ける。新しい体験例と文書の数字は `tests/example.test.ts` で確かめる。
11. **文書の金額は、アプリの計算の出力と一致させ、テストで照合する。** README、仕様、提出文、台本の架空の例の金額を `tests/example.test.ts` が計算して照合する。制度の数値と事実には出典の URL と確認日を付ける。
12. **社会の規模は、協会けんぽの令和 7 年度事業報告書の実績を使う。** 高額療養費（償還払い）104 万 2 千件・283 億円、現物給付 460 万 5 千件・6,628 億円（p.17、PDF の 22 枚目。2026-11-07 に PDF を取得して確認）。架空の例の差が 100 件なら 14,906,000 円という試算は「規模感で、達成予測ではない」と書く。償還払いには外来や合算も含み、1 件あたりにならすと約 2.7 万円で、架空の例の 149,060 円よりずっと小さいことも書く。
13. **測るものを決める。** 新たに窓口適用につながった件数、避けられた立替額、支払日の不足が解消した件数。今は測っていない。アプリは会話を保存せず、利用の記録も集めないので、測るなら同意を得た聞き取りになる。
14. **年表、あそぶ、かがみは、本筋のあとに家族の道具として短く触れるだけにする。** 台本でも本筋に入れない（入れるなら最後の 3 秒以内）。

| ---- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |

## 検討したほかの案

| 案                                                                                   | 採らなかった理由                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 筋書きの名前（Claude が付ける）で「上限を使う」「使わない」を見分ける                | 名前は自由な文で、言い回しが返答ごとに揺れる。順位を Claude に決めさせないのと同じ理由で、見分けもプログラムの額でする                                                                                  |
| 高額療養費と食事代の出力を画面で足して、2 つの額を作る                               | 画面で新しい額を作ることになる。見通しの計算（支払日の順、入金、手元のお金）と食い違うおそれがある                                                                                                       |
| 画面の部品を変えずに、計算（`lib/money/`）に「上限を使う・使わない」の欄を足す       | 依頼で計算と制度表には触らない。表示の層だけで、計算の出力から見分けられる                                                                                                                             |
| 体験例のお金のカードに、病院に聞く前と後の 2 つの見通しを残す                         | 本番の会話では、同じ道具を呼び直すと前の結果は表から外れる（`lib/money/attach.ts` の `combine`）。見本だけ違う画面になる                                                                                |
| 体験例を、病院の答えのあとの状態 1 つだけにする                                      | 2 つの額を並べた画面が見本に出ない。「答えを話すと更新される」も見せられない                                                                                                                            |
| 前の体験例のテストを、新しい例に書き直す                                             | 新しい例は額に幅が無く、不明点が筋書きの 1 つだけになる。幅の縮み方や、額の不明点の順位のテストが弱くなる                                                                                               |
| 副題を短くする（例:「支払日に間に合う準備へ」）                                      | 1079px 以下では副題を隠すので、長さの影響は 1080px 以上だけ。ヘッダーの折り返しとはみ出しの検査（320〜1,440px、外部リンクあり・なし）が通った                                                           |
| 月をまたぐ見通し（上限を使う筋書きが 2 本）でも、どちらかを選んで並べる               | どちらを出すかの基準が無い。幅と確認 1 つ（月ごとの内訳を病院に聞く）のほうが、その場面で伝えることに合う                                                                                                |

## 結果

良くなること:

- 開いて最初に読む一言と副題が、お金の準備の道具であることと、医療や給付の判断をしないことを伝える
- 「窓口で上限を使えば 115,690 円で 84,310 円残る。使わずにあとで還付なら 264,750 円で 64,750 円足りない。差の 149,060 円の一時立替を避けられる」が、計算の出力だけで 1 か所に並ぶ
- 体験例で、病院の答えを話すと見通しが更新されるところまで、Claude を呼ばずに試せる
- 文書の金額が計算の出力と食い違ったら、テストが落ちる

引き受けること:

- **月をまたぐ見通しでは、支払日の欄は出ない。** デモの 3 つ目の発言（1 週間延びる）のあとは、幅と確認 1 つが先頭になる
- **本番の数字は、Claude が置く筋書きで変わる。** 支払日（退院の日か月末か）、食事代の幅、月ごとの内訳は Claude が仮に置く。台本の数字は、プロンプトの指示どおりに置いた場合の計算で、撮影の前に本番で確かめる
- **録画済みの動画（v1）は、改修前の画面のまま。** 録り直しは PdM が行う（#37）
- **当事者の評価は 0 件。** 測るものを決めただけで、窓口適用につながったか、立替を避けられたかは確かめていない。動くことを、役に立つことの証拠にしない（ADR 0007）
- 1 件あたりの償還払いの平均は架空の例よりずっと小さいので、100 件の試算は大きめに見える。規模感としてだけ使う

見直す条件: 当事者が支払日の欄を見ても病院に確かめに行かなければ、何が止めているか（聞きにくさ、窓口の時間、マイナ保険証の登録）を確かめ直す。2027 年 8 月に限度額の区分が変わったら、制度表と例の数字を更新する。
