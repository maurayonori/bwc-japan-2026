# 0017. かがみ（撮影とプレビュー）をアプリの中に置き、映像をこの端末から出さず、カメラをこのサイト自身にだけ許す

- 状態: 採用（提出版に入れる。2026-11-07 に作者が決めた）
- 日付: 2026-11-07
- 関連: #54、[ADR 0014](0014-browser-speech-recognition-for-voice-input.md)（マイク）、[ADR 0015](0015-one-menu-for-sakiyomi-roadmap-and-play.md)（メニュー。かがみの扱いをこの ADR で置き換える）

## 背景

ADR 0015 では、かがみを `NEXT_PUBLIC_KAGAMI_URL` があるときだけ出す外部リンクにしていた。作者は、かがみを提出版のアプリの中に入れると決めた。機能は撮影とプレビューだけにする。合成は、その場で確かめられずに待ちが出るため、作者が外すと決めた。映像の解析と AI の呼び出しもしない。

カメラを使うには、応答のヘッダーの `Permissions-Policy` で `camera` を許す必要がある。今は `camera=()`（すべて禁止）。

## 決めたこと

1. **かがみはアプリの中のページ `/kagami` にする。** メニューでは あそぶ の次に置く。`NEXT_PUBLIC_KAGAMI_URL` とその分岐は消す。ペルソナは今のまま（`NEXT_PUBLIC_PERSONA_URL` があるときだけの外部リンク）。
2. **撮る。** 「カメラをつける」を押したときに初めて `getUserMedia` を呼ぶ（開いただけではカメラのランプをつけない）。撮っている映像を見ながら、録画を始めて止める。経過時間を出す。1 本の上限は 2 分で、`lib/kagami.ts` の `MAX_RECORDING_MS` に置き、過ぎたら自動で止める。音声も録るが、マイクが拒否されたら映像だけで撮る。カメラが 2 つ以上あれば切り替えられる。`facingMode` は希望でしかないので、切り替えは `enumerateDevices` の `deviceId` で別のカメラを指定し、表示と鏡写しは取得したトラックの設定（`getSettings` の `facingMode`）から決める。前のカメラは鏡のように左右を返して見せる（録る映像は返さない）。ボタンの文言は、設定で向きが確かなときだけ「うしろのカメラにする」「前のカメラにする」にし、分からないときは「ほかのカメラにする」。 上限の判断は `reachedLimit`（純粋関数）で、画面は 0.25 秒ごとに確かめる。**ファイルの実際の長さは、確かめる間隔と最後のかたまり（約 1 秒）の分だけ 2 分を超えることがある。** タブが隠れたら（`visibilitychange` で `hidden`）、録っている途中ならそこまでを残して止め、カメラとマイクのトラックも止める。戻ったときは「カメラをつける」をもう一度押してもらう（裏のタブで上限を過ぎて録り続けることもない）。`MediaRecorder.isTypeSupported` が無いブラウザでは、形式を MediaRecorder に任せる。 カメラを開く要求には番号を振り、取得の途中で画面を離れた・タブが隠れた・止めた・別の要求に替わったら、その要求の結果は使わない（映像だけで取り直さない。あとから返ってきたカメラはすぐ止める）。カメラが途中で切れたら（トラックの `ended`）、録っていればそこまでを残して止め、「カメラをつける」に戻す。`MediaRecorder.start` が失敗したら説明の文を出す。経過時間と長さは 2:00 に丸めず、実際の値を出す。
3. **見る。** 止めたらすぐに再生できる。撮り直す（いま撮ったものを消して撮る画面に戻る）、端末に保存する（ダウンロード）、残して続けて撮る、を選べる。このタブで撮ったものを新しい順に並べ、1 本ずつ再生・保存・消すができる。 撮った直後のプレビューは、人のいる場所で急に音が出ないよう、消音で始める（操作の部品から利用者が音を出す）。
4. **形式は `MediaRecorder.isTypeSupported` で選ぶ。** MP4（H.264・AAC）を先に試し、録れなければ WebM（VP9 か VP8・Opus）。どれも録れなければ MediaRecorder に任せる。保存するときの名前は端末の時刻で付ける（`kagami-YYYYMMDD-HHMMSS.拡張子`）。
5. **カメラが無いか拒否されたときは、動画を選ぶ形に切り替える。** `<input type="file" accept="video/*" capture="environment">` で選んだ動画を、撮ったものと同じように並べて見られる。カメラの API が無いブラウザでは、開いたときからこの形にする。 動画を選ぶ形に移るのは、拒否（`NotAllowedError`・`SecurityError`）とカメラが無いとき（`NotFoundError`）だけ（`cameraFailure`）。カメラが使用中（`NotReadableError`・`AbortError`）やそのほかのときは「カメラをつける」に戻し、「ほかのアプリがカメラを使っているかもしれません。閉じてから、もう一度押してください。」などと伝える。選んだファイルの MIME が空なら拡張子（mp4・m4v・mov・webm）で見分け、それ以外は断る文を出す（`videoTypeOf`）。
6. **撮ったものはこのタブのメモリにだけ置く。** `lib/kagami.ts` のモジュール変数に `Blob` と `blob:` の URL を置く。メニューで移ってもページを読み込み直さないので残り（ADR 0015 と同じ仕組み）、タブを閉じると消える。サーバーにもブラウザの保存領域（localStorage・sessionStorage・IndexedDB・Cache Storage）にも書かない。消すときは URL を解放する。画面に「映像はこの端末の外に出ません。タブを閉じると消えます。残すときは保存してください。」と書く。
7. **応答のヘッダーを `Permissions-Policy: camera=(self), microphone=(self), geolocation=()` にする。** カメラはかがみのため、マイクは入力欄の音声入力（ADR 0014）とかがみの録画の音声のために、このサイト自身にだけ許す。位置は使わないので禁じたまま。`X-Frame-Options: DENY` は変えないので、他のサイトの枠の中からは使えない。ブラウザは、カメラとマイクを使う前に利用者の許可を求める。
8. **発想の元の物語の名前、台詞、画像は使わない。** 見た目はさきよみのトークンに揃える。 「動画を選ぶ」はラベルの中の入力欄なので、キーボードで選んだときはラベルに、ほかのボタンと同じフォーカスの輪郭を付ける（`:focus-within`）。
9. **メニューに主従を付ける。** 作者が大会のストーリーを「使える制度を、支払日に間に合う準備へつなぐ」に絞ったので、主は 話す・見通し・渡すもの にし、区切りのあとの年表・あそぶ・かがみ（とペルソナ）は「家族の道具」として小さく控えめな文字で並べる。行き先と順番は変えない。「家族の道具」の名前は読み上げ用（`aria-label`）にだけ置き、画面には出さない（文字を増やすと散らかるため。出すかは作者が決める）。320〜1,440px でヘッダーの文字が途中で折れないことを e2e で確かめる。

## 確かめ方

- `tests/kagami.test.ts`: 2 分で止める判断（`reachedLimit`。直前・ちょうど・遅れて確かめた場合）、カメラの向きと鏡写し（`facingOf`・`mirrored`）、切り替える先（`nextCamera`）、ボタンの文言（`switchLabel`）、カメラを開けないときの扱い（`cameraFailure`）、選んだファイルの見分け（`videoTypeOf`）、形式の選び方、保存の名前、経過時間、メモリへの出し入れと URL の解放、保存領域・通信・合成や解析に当たるコードが無いこと、`next.config.ts` のヘッダー
- `e2e/kagami.test.ts`（Chromium の偽のカメラとマイク）: 撮る・止める・消音で始まるプレビュー・再生・端末に保存・撮り直す（最初の読み込みのあとから操作の終わりまで、1 つの見張りで `blob:` と `data:` 以外の通信が 0）、localStorage・sessionStorage・IndexedDB・Cache Storage が空で、`setItem`・`indexedDB.open`・`caches.open` の呼び出しも 0 回（スタブで記録。ファイルを選ぶ操作も通信の見張りの中）、メニューで年表へ移って戻っても残る、タブが隠れたら録画が止まって残りトラックが `ended` になる、時計を進めて 2 分で自動で止まる、カメラ拒否でファイル選択（検査の中で作った動画を再生できる、MIME が空の `.MOV` を受け、`.txt` を断る）、カメラ使用中は「カメラをつける」に戻る、カメラの API が無ければ開いたときからファイル選択、マイク拒否で映像だけ、`isTypeSupported` が無くても撮れる、偽のカメラ 2 つ（`device-count=2`）で切り替えると取得元の `deviceId` が変わり前のトラックが `ended` になる、取得の途中で画面を離れたら取り直さない、タブが隠れたあとに返ってきたカメラはすぐ止まる、カメラが途中で切れたら残して「カメラをつける」に戻る

## 検討したほかの案

| 案                                                       | 採らなかった理由                                                                                                       |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 撮った映像に合成をかける                                 | その場で確かめられず待ちが出る。作者が外すと決めた                                                                     |
| 撮った映像を IndexedDB に残し、次に開いたときも見られる  | 「保存しない（閉じると消える）」の約束が弱くなる。共有の端末に映像が残る。残したいときは端末に保存すれば足りる         |
| 開いたときにすぐカメラをつける                           | 押していないのにカメラのランプがつく。許可の問いが先に出て、何のページか分かる前に答えることになる                     |
| かがみを外部リンクのまま残す                             | 作者が提出版のアプリの中に入れると決めた                                                                               |
| `camera=*` にして、ほかのサイトの枠の中でも使えるようにする | 枠の中で使う理由が無い。`X-Frame-Options: DENY` と合わせて、このサイト自身だけにする                                   |

## 結果

- メニューの かがみ から、撮る・すぐ見返す・端末に保存するができる。映像はこの端末の外に出ない
- カメラを許可しない人や、カメラの無い端末でも、端末の動画を選んで同じように見返せる
- この変更の push は、作業ブランチの古い履歴（マージ済みの PR #53）を置き換える操作がこの作業の環境で止められたため、別の名前のブランチ `claude/kagami-54` にした（作者の判断）
- 見直す条件: 撮ったものをタブを閉じても残したいという要望が出たとき（保存の場所と消し方を先に決める）。合成など、映像に手を加える機能を入れるとき
