# 0018. 照らせない金額と日付は採用せず、確認の順位は要る額への効き方と中間の境目で決める

- 状態: 採用
- 日付: 2026-11-07（#61 のレビューを受けて 2026-11-08 に改訂）
- 関連: #59、#61、#63、#66、#70、#76、[ADR 0013](0013-decision-first-range-and-one-check.md)、#46

## 背景

外部レビュー（Codex）で、「金額と日付はプログラムが計算したものだけを見せる」という約束をすり抜ける経路と、「まず確かめる 1 つ」の順位の誤りが見つかった（#59）。

- 計算にも発言にもない金額をカードに書かれると、注意は出るが、カードは採用され、持ち出しの文には注意なしで入る
- 「残しておく言葉」は本文だけを原文と照らしていて、見出しや次の行動は作れる
- 照合の根拠に、失敗した計算の入力、年齢や日数のような金額でない数字が入る。年のある日付を月日だけで照らし、曜日を照らさない。¥ 付きや漢数字の金額を拾わない
- 順位の候補を生の金額の幅で 6 つに絞るので、要る額に効く支払いが落ちる
- 確かめると残る幅を、少なめと多めの端だけで測るので、要る額を決める支払いの時点が切り替わる中間の額で、残る幅を小さく見積もる

## 決めたこと

1. **照らせない金額・日付を含むカードは採用しない。** 前の版があれば画面に残り、無ければ出さない。お金のカードは、表はプログラムの計算なので残し、見出しを含む欄の照らせない部分だけを伏せる（#61 で、欄ごと決まった文に替えるのをやめた）。返答の本文の照らせない金額・日付は伏せ、短い注記を足す。注意（「確かめてほしいこと」）は今までどおり出す
2. **「残しておく言葉」の見出しは原文の最初の一文、次の行動は決まった文にする。** 本人が直したものはそのまま持ち出す
3. **照合の根拠を絞る。** 成功した計算の入力と結果だけを使う。日数・回数・割合などの項目は金額の根拠にしない。年のある日付（和暦の令和も）は年月日で、曜日（括弧の無い「日曜日」も）はプログラムが計算した曜日と照らす。会話の前の返答に書いた額と日付は、そのときに照らし終えた値なので根拠に残す（計算を置き換えたあとの「前は ◯ 円でした」を伏せないため）
   - 額は、返答でも利用者の発言でも、同じ取り出し方で**額の全体ごと**に取り出す。円・¥・￥ のどれか、または万・千・億と数字があれば額とみなす（「12万」「28万ほど」）。空白や単位のまざった書き方（「11万 5,690円」「￥12万3千」）は 1 つの額として読む。途中まで重ねて取り出さない（「12万3千円」から 120,000 円を作らない）。歩・歳・人・日間などの単位が続く数字（「三千歩」「4万人」）は額にしない
4. **給付の断定と、連絡・申請の代行の完了を言う文は、決まった案内に置き換える。** 問いかけ（「申請しましたか」）や勧め（「必ず確かめてください」）は置き換えない
   - 見出しを含め、生成した欄をすべて見る。見出しは短いので、見出しごと決まった短い文にする。「給付金は支給されます」のような強調の語の無い断定も置き換える
   - 完了を言う文は、済ませた人（完了した行為のすぐ前の主語）と結び付けて判断する。本人や家族（夫・妻・母・父・子など）の完了の報告は、本人の発言に同じ報告（同じ人が、同じ手続きを）があるときだけ残す。本人の発言をそのまま写した文は、返答でもカードでも残す。アプリが行ったと読める文（「代わりに」「こちらで」「しておきました」）は、「あなたが」などがあっても置き換える。返答はアプリの声なので、返答の「私」と、主語の無い完了はアプリとして扱う
5. **確認の順位は、要る額への効き方で決める。** 要る額は支払いが増えれば増え、入金が増えれば減る。そのため、ある不明点を決めたときの要る額の上限と下限は、ほかの不明点を両端に置いた 2 通りで求まる。この方法で、すべての候補について確かめたときに残る幅を先に測り、縮み方の大きい順に 6 つを枝の表に出す。表に入れなかった候補があるあいだは、読み方とプロンプトで「一番」と言い切らない
6. **残る幅は、少なめと多めのあいだの境目でも測る。** 不明点の額を少なめから多めまで動かすと、日付順の累計はその額の一次式になり、要る額はその最大になる。一番上の線が入れ替わる点（要る額を決める支払いの時点が切り替わる境目）で残る幅を測る。一次式の値は、両端で台帳の計算と一致することを毎回確かめ、合わなければ境目は使わない
7. **高額療養費の計算記録は、道具の名前と診療月で区別して置き換える**
8. **返答が書いた「要る額」の範囲（「X 円から Y 円」「X〜Y 円」）は、最新の計算の範囲と照らす。** 数字が 1 つずつ計算にあっても、別の筋書きの額を組み合わせた範囲は表と食い違うため。合わなければ注意を出し、伏せる。条件をつけた範囲（「〜場合」「〜なら」「〜とき」）は、その条件に当たる筋書き（名前か、筋書きを区別する入出金の label で結び付ける。条件全体が名前に入っている筋書きを先に使い、無ければ名前の一部で結び付ける）の範囲と照らし、結び付けられなければ照らさない（取りこぼしを許し、正しい返答を伏せないほうを取る）。幅の縮みを言う部分（「◯ 円から ◯ 円に縮みます」）と、前の値を言う範囲（文の中で範囲より前に「前の」などがあり、そのあいだに別の額も「今の」「ですが」なども無いもの）だけは照らさない。持ち出しでは、範囲はそのカード自身の計算と照らす。プロンプトでは、条件が変わったとき（仮の問いも）は新しい条件の筋書きだけを置き、前の額は「前は ◯ 円でした」と書かせ、差額を書かせない
9. **後処理（伏字・注記・決まった案内）のあとの長さを、画面の形の上限に収める。** 文の終わりで切り、注記は残す。途中で切れた数（全角も）は、数ごと外す。上限を超えて返答ごと捨てられ、表まで失うことを防ぐ
10. **持ち出す直前にも検査する。** 本人が直していないカードの文を、カードの計算・会話・出典と照らし、照らせない部分を伏せる。前の版で保存したカードが、そのまま家族や窓口へ渡らないようにする。本人が直したカードと「残しておく言葉」は触らない

## 検討したほかの案

| 案 | 採らなかった理由 |
| --- | --- |
| 照らせないカードも、注意を付けて採用する（今まで） | 持ち出しの文に注意なしで入り、約束が守れない |
| 照らせない数字だけを伏せてカードを採用する（お金のカード以外） | 家族に渡す文が穴あきになり、意味が変わるおそれがある。前の版を残すほうが安全。お金のカードは表がプログラムの計算で、欄ごと替えると正しい見出しや文まで消えるので、#61 から部分だけを伏せる |
| 置き換えた前の計算をカードに残し、照合の根拠にする | 表や保存データの形が変わり、画面が変わる。前の返答に書いた値は、照らし終えた値なので、それを根拠にすれば足りる |
| 円の付かない数字もすべて額とみなす | 日数・人数・歩数を額として照らし、正しい文を伏せてしまう |
| 「残しておく言葉」の見出しも原文との一致を検査し、合わなければ落とす | 体験例の見出しが通らなくなる。見出しは原文から作るほうが単純で確か |
| 順位の候補を、生の金額の幅で絞る（今まで） | 要る額に効かない入金が多いと、効く支払いが落ちる |
| 少なめと多めのあいだを、決まった刻みで測る | 境目が刻みの間にあると測りこぼす。境目は一次式から正確に求まる |
| 返答を自動で書き直させる | 往復と時間が増える。#46 と同じく、注意と伏せ字で受ける |

## 結果

- カードと持ち出しの文に、照らせない金額・日付が入らなくなる。その代わり、Claude の文が照らせないときは、カードが更新されないことがある（注意で理由を伝える）
- 計算の結果の数字と、体験例とストーリーの数字（115,690 円・264,750 円・差 149,060 円）は変わらない
- 試作との数字の検査の突き合わせは、試作に無い年と曜日の指摘を除いて比べる
- 会話の前の返答は画面から送られてくるので、利用者の発言と同じく、利用者が書き換えられる。この検査は Claude の書き誤りを防ぐためのもので、利用者自身の改変を防ぐものではない
- 検査の取りこぼし（小数の千、漢数字の和暦の年、金額でない単位の一部）は #63 に残した
- #66 で足したこと: 月をまたぐ入院で、月ごとの窓口負担を同じ筋書きの中で 0 円からの別々の幅として置いた入力は、計算の前に道具のエラーで差し戻す（2 か月の合計は総額で決まっているため）。足りない額を「足ります」、残る額を「足りません」と逆の向きで書いた文は、計算から作った文（筋書きの名前と「◯ 円足りない／◯ 円残る」）に置き換え、注意で伝える。言い方がまざって判別できない文は置き換えない。条件と筋書きの結び付けは、名前の部分がすべて条件に入っている筋書きだけを使う。済ませた人は、従属節の主語（「私が入院している間に」）を外して読み、判別できなければ置き換えない。前の値の範囲は、「今の」「でしたが」などの切り替えの語が無ければ照らさない
- #67 の確認で絞ったこと: 月ごとの幅の差し戻しは、どの月にも「0 円から同じ額まで」を渡した高額療養費の計算と一致する幅（決まった総額を月ごとの独立した幅に広げたと確かめられるもの）だけにした。病院が月ごとに言った幅は受け付ける。従属節の主語として外すのは、ほかにも主語があり、その主語のすぐあとに述語と従属節の印（「入院している間に」）が続くときだけにした（「退院前に」「仕事の合間に」では外さない）。足りない額の向きは、準備の方法を言う条件の文（「追加すれば」）と問いの形の文（「足りるかどうか」）では置き換えない。筋書きを見分ける部分は、短くても（「半々」）一致の条件に入れる
- #71 で足したこと: 資金を足す動き（追加・用意・補う・準備・工面・借りる など）がある文は、活用形によらず条件の文として、足りない額の向きを置き換えない
- #71 で足したこと: 本人の発言に家族と「私が／私は」の両方が主語として出てくる完了の報告は、済ませた人を判別できないとして、返答の家族の完了報告を置き換えない
- #71 で足したこと: 文の最後の「要る額」から範囲までに「幅」があり、「X 円から Y 円」と書いた範囲（「要る額の幅は149,060円から0円になります」）は、幅が変わることを言う文として、要る額の範囲とは照らさない。一つずつの額の照合は残す
- #76 で絞ったこと: 例外が広すぎて誤りを通していたので、次のように絞った。資金を足すことを打ち消す文（「追加の用意はいりません」）は例外にしない。資金を足す動詞のあとに条件の語（ば・と・たら・なら・ことで）が続く文だけを条件の文とみなす。「幅」の例外は、範囲のすぐあとに変化の語（「に縮」「になり」「になる」「に狭」「に変わ」「に減」）が続くときだけにする。済ませた人を判別できないとみなすのは「（家族）は私が…（間に・ときに・うちに）」の形だけにし、本人がしていないと明示した文は例外にしない
- #76 で足したこと: 道具の入力と出力の文字列のうち、Claude が自由に書ける label と name（筋書きの名前・入出金や段取りの名前と、それを写した出力）は、額と日付の根拠にしない。区分の条件などのプログラムが作った文は、今までどおり使う。額や日付の無い給付の断定（「給付は確定しています」「必ず支給されます」）と、代行の言い切り（「こちらで病院へ電話しておきました」「申請しておきました」）も置き換える。利用者や家族が主語の文（「夫が電話しておきました」）は置き換えない
- #78 で足したこと: 資金を足すことの打ち消しに「必要がありません」「必要ではありません」も含める。条件の「と」は読点が無くても拾い、資金を足す条件の節がある文は打ち消しがあっても残す。「幅」の変化の例外は「から」でつないだ範囲だけにし、変化の語に「となり」「となる」「にまで」を足す。「」『』の中（電話の台本や引用）は、済ませた・代行したの検査から外す。「電話」「手配」は、アプリが行ったと読める形（「こちらで…電話しました」「電話しておきました」）だけを対象にする
- 既知の限界: 利用者が「夫は私が留守の間に、保険会社に連絡しましたが、私はまだ連絡していません。」と話したあと、正しい「ご主人が保険会社に連絡しました。」が置き換わり、誤った「あなたが保険会社に連絡しました。」が残る（1 文に家族の報告と本人の否定がまざる形）
- 既知の限界: 「あなたが希望されたとおり、こちらで申請しておきました。」が残る（「あなたが」を主語として読み、アプリの代行と読めない）
- #78 の後退の直し: 条件の「と」は動詞の終わりのすぐあとだけにし（「不要だと」「と考え」は条件にしない。「足すと」は拾う）、打ち消しのすぐあとが「か」の文（「必要がないか」）は問い・確認の文として置き換えない。利用者の発言から済ませたことを読む側では「電話しました」「手配しました」も数える（返答の代行の言い切りを見る側は、狭い形のまま）
- 既知の限界: 返答の「申請の状況は『申請済みです』。」が残る（括弧の中を、済ませた・代行したの検査から外しているため）
- 既知の限界: アプリの声の返答「私が病院に電話しました。」が残る（「電話」は、アプリが行ったと読める狭い形だけを対象にしているため）
- #82 で足したこと: 同じ返答で見通し（simulate_cashflow）が複数呼ばれたとき、「最後の見通し」ではなく、その回の内訳の計算（高額療養費の窓口で払う額・上限の無いときの負担、食事代、その和）の額を入出金に含む最後の見通しを本線にする（`lib/money/main-cashflow.ts`）。本番で Claude が正しい見通しのあとに筋書き「x」・1 円の試し呼びをし、正しい額が伏せられ表の先頭が 1 円になった。内訳の計算が無い回や、どの見通しも内訳の額を含まないときは、今までどおり最後の見通し。試し呼びの記録は消さず、カードの計算の並びで本線を最後に置く（画面・持ち出し・検査はすべて最後の見通しを見るため）
- #78 の最後の回で直したこと: 打ち消しのあとの問いの「か」は「か、」「か。」「かどうか」「かを」だけにする（「必要がないから」は打ち消し）。「足さずに済むと思います」は条件にせず、「と」のあとの除外は「とは限らない」「といった」「という」「と考え」「と思」「として」だけにする。「追加したとき」も条件として拾う。利用者の 1 文にある完了の報告はすべて拾う。「手配」は申請とは別の行為として数える。全回の再現文を、表の形の固定テスト（`tests/guard-regressions.test.ts`）にまとめた
- 既知の限界: 利用者が台本を相談する文（「病院には『入院の件で電話しました』と言えばいいですか。」）を、電話した報告として数える（利用者の発言の括弧の中は、報告の読み取りから外していないため）
- #85 で直したこと: 本線の見通しは、今回の回に見通しがあれば今回の見通しから選び、今回に無いときだけ前の回までさかのぼる（照らす基準の内訳の額は、前の回の分も含めて全体から集める）。#82 の選び方を、検査に渡す前の回のカードの計算と今回の記録をつないだ全体に当てはめたため、今回の見通しの入出金に内訳の額が無いと前の回の見通しが本線になり、正しい幅を伏せていた。足りない額の向きの検査と、持ち出しの検査（そのカード自身の計算から選ぶ）も同じ選び方にした。前の回の計算は、「前は ◯ 円でした」を照らす根拠として残す
- #87 の後退の直し: 見通しかどうかの判定を、保存データの形（`cashflowOutputSchema`）に合わせた。「まず確かめる 1 つ」より前の旧形式（what_to_confirm の無い見通し）も見通しとして数えないと、持ち出しで別のカードの見通しを本線に選び、「84,310円残ります」を「84,310 円足りない」に書き換えていた
- 既知の限界: 計算を持たないカード（質問文のカードなど）を持ち出すと、そのカードの見通しを特定できず、ほかのカードの見通しで照らす。どのカードの見通しで照らすかは、カードの並びで変わる
- 既知の限界: 「追加で10,180円を用意する必要がないかは、支払日の前に確認しましょう。」のように、問いの「か」のあとに「は」が続く確認の文を、打ち消しとして照らし、置き換える
- 既知の限界: 利用者の「申請しましたら連絡します」のような、これからのことを言う文を、済ませた報告として数える
- 既知の限界: 済ませた人を判別できない形（「（家族）は私が…間に」）が 1 文にあると、同じ文のほかの節の報告まで、判別できないものとして扱う
- 既知の限界（2026-11-08、#114）: 額は円・¥・￥ か万・千・億のある書き方だけを取り出すので、返答に英語の「350,000 yen」がそのまま書かれると照らさない（伏せない）。利用者の英語の「yen」の額と、「12月5日から15日まで」の「15日」のように月を省いた日は、利用者が言った値として数えないので、Claude が「35万円」「12/15」と言い換えると、計算の結果などほかの根拠にも同じ値が無いときは伏せる。照合を緩める直し（#110）は、話していない日付を通す形が見つかったので外した
- 限界: 条件と筋書きの結び付け、済ませた人、前の値の読み取りは、語の並びによる簡単な読み方で、文の意味までは読まない。読み違えたときは、伏せずに通す側（取りこぼし）に倒すようにしている。完了の報告は、主語が書かれていない文を、返答ではアプリ、カードでは本人として扱う
- 見直す条件: 実 API でカードが採用されない場面が多いとき（照らせる書き方をプロンプトで促す）、境目の計算が台帳と合わずに使われない場面が見つかったとき、範囲の照らし合わせが正しい文を伏せる場面が見つかったとき
