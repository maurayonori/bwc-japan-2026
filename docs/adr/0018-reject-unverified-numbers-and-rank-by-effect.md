# 0018. 照らせない金額と日付は採用せず、確認の順位は要る額への効き方と中間の境目で決める

- 状態: 採用
- 日付: 2026-11-07（#61 のレビューを受けて 2026-11-08 に改訂）
- 関連: #59、#61、[ADR 0013](0013-decision-first-range-and-one-check.md)、#46

## 背景

外部レビュー（Codex）で、「金額と日付はプログラムが計算したものだけを見せる」という約束をすり抜ける経路と、「まず確かめる 1 つ」の順位の誤りが見つかった（#59）。

- 計算にも発言にもない金額をカードに書かれると、注意は出るが、カードは採用され、持ち出しの文には注意なしで入る
- 「残しておく言葉」は本文だけを原文と照らしていて、見出しや次の行動は作れる
- 照合の根拠に、失敗した計算の入力、年齢や日数のような金額でない数字が入る。年のある日付を月日だけで照らし、曜日を照らさない。¥ 付きや漢数字の金額を拾わない
- 順位の候補を生の金額の幅で 6 つに絞るので、要る額に効く支払いが落ちる
- 確かめると残る幅を、少なめと多めの端だけで測るので、要る額を決める支払いの時点が切り替わる中間の額で、残る幅を小さく見積もる

## 決めたこと

1. **照らせない金額・日付を含むカードは採用しない。** 前の版があれば画面に残り、無ければ出さない。お金のカードは、表はプログラムの計算なので残し、見出しを含む欄の照らせない部分だけを伏せる（#61 で、欄ごと決まった文に替えるのをやめた）。返答の本文の照らせない金額・日付は伏せ、短い注記を足す。注意（「確かめてほしいこと」）は今までどおり出す
2. **「残しておく言葉」の見出しは原文の最初の一文、次の行動は決まった文にする。** 本人が直したものはそのまま持ち出す
3. **照合の根拠を絞る。** 成功した計算の入力と結果だけを使う。日数・回数・割合などの項目は金額の根拠にしない。年のある日付（和暦の令和も）は年月日で、曜日（括弧の無い「日曜日」も）はプログラムが計算した曜日と照らす。会話の前の返答に書いた額と日付は、そのときに照らし終えた値なので根拠に残す（計算を置き換えたあとの「前は ◯ 円でした」を伏せないため）
   - 額は、返答でも利用者の発言でも、同じ取り出し方で**額の全体ごと**に取り出す。円・¥・￥ のどれか、または万・千・億と数字があれば額とみなす（「12万」「28万ほど」）。空白や単位のまざった書き方（「11万 5,690円」「￥12万3千」）は 1 つの額として読む。途中まで重ねて取り出さない（「12万3千円」から 120,000 円を作らない）。歩・歳・人・日などの単位が続く数字（「三千歩」「4万人」）は額にしない
4. **給付の断定と、連絡・申請の代行の完了を言う文は、決まった案内に置き換える。** 問いかけ（「申請しましたか」）や勧め（「必ず確かめてください」）は置き換えない
   - 見出しを含め、生成した欄をすべて見る。見出しは短いので、見出しごと決まった短い文にする。「給付金は支給されます」のような強調の語の無い断定も置き換える
   - 完了を言う文は、アプリが行ったと読めるものだけを置き換える。本人や家族が主語の文と、カードが写した本人の発言（「私はすでに保険会社に申請しました。」）は置き換えない。返答はアプリの声なので、返答の「私」はアプリとして扱う
5. **確認の順位は、要る額への効き方で決める。** 要る額は支払いが増えれば増え、入金が増えれば減る。そのため、ある不明点を決めたときの要る額の上限と下限は、ほかの不明点を両端に置いた 2 通りで求まる。この方法で、すべての候補について確かめたときに残る幅を先に測り、縮み方の大きい順に 6 つを枝の表に出す。表に入れなかった候補があるあいだは、読み方とプロンプトで「一番」と言い切らない
6. **残る幅は、少なめと多めのあいだの境目でも測る。** 不明点の額を少なめから多めまで動かすと、日付順の累計はその額の一次式になり、要る額はその最大になる。一番上の線が入れ替わる点（要る額を決める支払いの時点が切り替わる境目）で残る幅を測る。一次式の値は、両端で台帳の計算と一致することを毎回確かめ、合わなければ境目は使わない
7. **高額療養費の計算記録は、道具の名前と診療月で区別して置き換える**
8. **返答が書いた「要る額」の範囲（「X 円から Y 円」「X〜Y 円」）は、最新の計算の範囲と照らす。** 数字が 1 つずつ計算にあっても、別の筋書きの額を組み合わせた範囲は表と食い違うため。合わなければ注意を出し、伏せる。幅の縮み方を言う文と、前の条件の額を言う文は照らさない。プロンプトでは、条件が変わったとき（仮の問いも）は新しい条件の筋書きだけを置き、前の額は「前は ◯ 円でした」と書かせ、差額を書かせない
9. **後処理（伏字・注記・決まった案内）のあとの長さを、画面の形の上限に収める。** 文の終わりで切り、注記は残す。途中で切れた数は残さない。上限を超えて返答ごと捨てられ、表まで失うことを防ぐ

## 検討したほかの案

| 案 | 採らなかった理由 |
| --- | --- |
| 照らせないカードも、注意を付けて採用する（今まで） | 持ち出しの文に注意なしで入り、約束が守れない |
| 照らせない数字だけを伏せてカードを採用する（お金のカード以外） | 家族に渡す文が穴あきになり、意味が変わるおそれがある。前の版を残すほうが安全。お金のカードは表がプログラムの計算で、欄ごと替えると正しい見出しや文まで消えるので、#61 から部分だけを伏せる |
| 置き換えた前の計算をカードに残し、照合の根拠にする | 表や保存データの形が変わり、画面が変わる。前の返答に書いた値は、照らし終えた値なので、それを根拠にすれば足りる |
| 円の付かない数字もすべて額とみなす | 日数・人数・歩数を額として照らし、正しい文を伏せてしまう |
| 「残しておく言葉」の見出しも原文との一致を検査し、合わなければ落とす | 体験例の見出しが通らなくなる。見出しは原文から作るほうが単純で確か |
| 順位の候補を、生の金額の幅で絞る（今まで） | 要る額に効かない入金が多いと、効く支払いが落ちる |
| 少なめと多めのあいだを、決まった刻みで測る | 境目が刻みの間にあると測りこぼす。境目は一次式から正確に求まる |
| 返答を自動で書き直させる | 往復と時間が増える。#46 と同じく、注意と伏せ字で受ける |

## 結果

- カードと持ち出しの文に、照らせない金額・日付が入らなくなる。その代わり、Claude の文が照らせないときは、カードが更新されないことがある（注意で理由を伝える）
- 計算の結果の数字と、体験例とストーリーの数字（115,690 円・264,750 円・差 149,060 円）は変わらない
- 試作との数字の検査の突き合わせは、試作に無い年と曜日の指摘を除いて比べる
- 会話の前の返答は画面から送られてくるので、利用者の発言と同じく、利用者が書き換えられる。この検査は Claude の書き誤りを防ぐためのもので、利用者自身の改変を防ぐものではない
- 見直す条件: 実 API でカードが採用されない場面が多いとき（照らせる書き方をプロンプトで促す）、境目の計算が台帳と合わずに使われない場面が見つかったとき、範囲の照らし合わせが正しい文を伏せる場面が見つかったとき
