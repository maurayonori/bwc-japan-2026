## テーマ（どちらか 1 つ）

どちらのテーマも、暮らしている地域や日本の具体的な現場の課題を、Claude Code で解くことが前提です。

1. **あなたにしかない深さを。** 仕事・地域・技術・趣味など、自分が一番よく知っている世界から始めます。その世界の隣にいる仲間や、あとを引き継ぐ人が使うものを作ります
2. **本来、誰にでも届くべきものを。** 専門知識・費用・言語・手続きの壁で、助けを受けられずにいる人に届けます。高齢化・人手不足・災害への備えといった、日本社会の課題も対象になります

## 審査基準

| 基準          | 配点 | 見られること                                                                                                                                                |
| ------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| インパクト    | 30%  | 課題が自分の仕事・暮らし、または日本の具体的な現場から出ているか。誰が、どんな場面で、どれくらい困っているか。ハッカソンのあとも使われ続けるか              |
| デモ          | 25%  | 冒頭で「誰の、どんな課題を、どう解くか」が分かるか。前提知識の無い人にも価値が伝わるか。最後まで見たくなるか                                                |
| Claude の活用 | 25%  | 基本的な使い方を超えているか。Claude Code を開発の中心に置いているか。モデルや機能（Skills、サブエージェント、MCP、フックなど）を目的に合わせて選んでいるか |
| 深さと実行力  | 20%  | 試行錯誤して磨いた跡があるか。設計と実装が丁寧か。困っている人が安心して使える形か。**リポジトリを見て判断される**                                          |

## ルール

| 項目         | 内容                                                                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 公開         | デモで見せるものは、すべて公開リポジトリに置いて提出する                                                                                             |
| 新規開発のみ | 開発はキックオフ後に始める。期間前に作ったものは使えない。デモで期間中に作ったものと区別できなければ失格。仕様書や構想を事前に書いておくのは構わない |
| 権利         | 使用権の無いコード・データ・素材を使ったものは失格。法律・倫理・プラットフォームの規約に反するものも失格                                             |
| 外部の協力   | 当事者へのインタビューなど、仮説の検証や素材づくりの協力は受けてよい。コードを書くのは参加者だけ                                                     |
| 言語         | 提出物はすべて日本語                                                                                                                                 |

### 作らないもの

参加者ガイドが、作ってはいけない汎用的な例として挙げているものです。

- メンタルヘルスの助言
- 基本的な RAG（文書を検索して答えるだけのもの）
- Streamlit で作ったアプリ
- 画像解析
- 教育向けのチャットボット
- 履歴書の選別
- 栄養の助言
- 性格診断
- 医療の助言
