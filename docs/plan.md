# 進め方（11/3〜11/8）

11/3 のセッション「仕様作成と Managed Agents」で示された手順を、このプロジェクトに当てはめたものです。出どころは Discord #hackathon-stage のセッション（録画は #資料-resources）。

## 手順

セッションで示された流れは「アイデア → 言語化 → 仕様作成 → タスク分解 → 実装 → ビルド → 検証」で、最初の 3 つが土台になる。7 日のうち 1〜2 日を計画に使ってよい。

1. **分かっていること・分かっていないことを書き出す**（下の一覧）
2. **Claude に聞き取りをさせて仕様書を作る。** 自分で仕様を書くと、書かなかった部分を Claude が勝手に決めてズレる。一度に 30〜50 問を出す形は負荷が高いので、Claude Code の質問ツール（選択式・おすすめ付き・自由記入あり）で 1 問ずつ答える。終わりの条件は「決まったこと・まだ決まっていないこと」の一覧が出ること。出力は `docs/spec.md`
3. **仕様書をタスクに分解してから作る。** 1 タスクを 1 Issue にし、依存の無いものは並列に進める
4. 実装・ビルド・検証。曖昧なまま作らせない。「いい感じに」は使わない

## 分かっていること（11/3 時点）

[ADR 0002](adr/0002-topic-gaps-left-by-existing-apps.md) で決めたこと。

- 使う人は親だけ。札幌で就学前の子を育てる家庭で、保育園に通っているかは問わない
- 課題は、手続きとお金・任意接種の時期と費用・預け先の事前登録・家族ごとの次の一手を、時期ごとに知らずに損をする／慌てること
- 既存のアプリにあるものは作らない。定期接種と健診（母子モ）、日々の記録（ピヨログ）、園との連絡（ルクミー）
- 医療・栄養の助言、手続きの代行、写真の読み取りはしない
- 最初の入力は生年月日・区・働き方くらいに抑える。済んだことは一言で反映する
- 日付と、対象になるかの判定はプログラムで計算する。Claude に生成させない
- 制度の項目には出典 URL と確認日を付ける
- テーマは 2。締切は 11/8 20:00。デモは 3 分。コードはすべて 11/2 12:30 以降に書く
- 札幌の制度で確かめた事実: 病児保育は予約システム（テオテ）と施設ごとの登録が要り、予約は前日 12 時から。子サポは説明会と顔合わせが済むまで頼めない。緊サポは希望どおり使えないことがある

## 分かっていないこと（聞き取りで決める）

### 何を出すか

- 制度データの範囲。最初に入れる手続き・接種・預け先は何件か。区ごとの違いをどこまで持つか
- 「家族ごとの次の一手」の定義。働き方（育休中・復職・自営）や保育園の有無で、何がどう変わるか
- いつ知らせるか。期日の何日前に、どの手段で出すか
- 母子モ札幌版の実画面に、任意接種や手続きの案内が本当に無いか

### どう作るか

- 制度データの作り方。公式ページから Claude に抽出させて人が確かめるのか、手で書くのか。更新をどう続けるか
- Claude の役割。一言の更新の解釈、次の一手の説明、データの抽出、当事者への聞き取り、のどれを担うか
- 画面の形。Web か、CLI か、LINE などのメッセージか。スマホで使うか
- データの持ち方。ブラウザの中だけか、サーバーに置くか。家族で共有するか
- デプロイ先。公開して動かすか、ローカルで動かして見せるか
- Managed Agents を使うか。使うなら何を任せるか
- 日付計算の正しさをどう検証するか（テストの形）

### 見せ方

- デモで見せる架空の家族と、3 分の流れ
- 名前（#2）

## Claude Code の使い方

審査の「Claude の活用」は、Claude Code を開発の中心に置いているかを見る。セッションで示された使い方を、そのまま採る。

- **聞き取り**: Claude Code の質問ツール（選択式・おすすめ付き・自由記入あり）で 1 問ずつ答える。`/goal` に「`docs/spec.md` に決まったこと・まだ決まっていないことの一覧がある」を置き、未達なら続けさせる。`/goal clear` で解除
- **精査**: `/advisor opus` で上位モデルに出力を精査させる（実験的な機能。Anthropic API 経由のみで、使用量は加算される。使えない口では無しで進める）
- **タスク分解のあと**: 依存の無い Issue はサブエージェントで並列に進める。1 タスクを 1 Issue・1 コミットにする
- **Managed Agents**: 使うかは仕様で決める。使うなら同梱の claude-api スキル（`/claude-api managed-agents-onboard`）と `ant` CLI で作る。`ant` の認証情報は Claude Code に拾われうるので、使い終わったら `ant auth logout` する。`ANTHROPIC_API_KEY` はシェルに export しない（大会用の鍵は `.env` にだけ置く）
- 実装は bwc-japan-2026 を開いた Claude Code（大会用の Max）で行い、ハーネス側のセッションは記録と壁打ちに使う
