11/3〜4 に Claude Code の質問ツールで作者に聞き取りをして初版を作り、外部レビュー（Codex）の指摘を確かめて第 2 版にし、11/4 に公的調査と競合（LINE ヤフー Agent i）を確かめて第 3 版にし、同日に作者の指摘で主画面を「12 か月の見通し」にして第 4 版にした。題材は [ADR 0002](adr/0002-topic-gaps-left-by-existing-apps.md)、範囲を削った判断は [ADR 0003](adr/0003-first-version-scope-cuts.md)、ニーズの根拠と第一声は [ADR 0004](adr/0004-evidence-from-public-surveys-and-registration-first.md)、見通しの画面は [ADR 0005](adr/0005-twelve-month-outlook-as-main-screen.md)、進め方は [plan.md](plan.md)。末尾に「決まったこと」「まだ決まっていないこと」の一覧がある。

## 1. 誰の、何を解くか

- 使う人: 札幌市で就学前の子どもを育てる親。保育園に通っているかは問わない
- 困りごと: 手続き・お金・任意接種・預け先の事前登録を、時期ごとに知らずに損をする、または直前に慌てる。既存のアプリ（母子モ・ピヨログ・ルクミー）はここを扱わない。預け先の事前登録をしていない保護者は 66.5%（東京都、6,181 人）、病児保育を使わなかった理由の 2 位は「事前登録をしていなかった」39.3%（函館市、1,454 人）。出典は ADR 0004
- 第一声: 「困った日には間に合わない登録を、先に済ませる」。LINE ヤフーの Agent i 子育てエージェント（2026-10-14 提供開始）は自治体の手続き・助成金を AI が TODO 化するが、預け先の事前登録・親の働き方の軸・出典と確認日・期限の計算・通知は無い。ここで差を付ける
- 解き方: 子どもの生年月日・区・親の働き方・保育園の有無（任意で入園予定月・第 2 子の予定日）から、その家庭の「これからの 12 か月の見通し」を月ごとに出す。レーンは 3 つ: 起きうること（通園できない日数の目安・親が休む日数・流行期）／先に済ませること（登録・手続き・受けられる接種を期日の近い順に）／お金（給付が入る月・費用・助成）。済んだことは一言で消せる。各項目に費用・窓口・出典・確認日が付く（ADR 0005）
- 使う前提: 通知は作らない。最初の設定の最後に「毎月 1 日に開く」と案内し、ホーム画面への追加を勧める

## 2. 範囲

### 出すもの

| 領域                 | 例                                                                                                  | 優先 |
| -------------------- | --------------------------------------------------------------------------------------------------- | ---- |
| 手続きとお金         | 出生届・児童手当・子ども医療費助成・育休給付・保育園の申込・保育料                                  | 1    |
| 任意接種の時期と費用 | インフルエンザ・新型コロナ・おたふくかぜ・RS ウイルスなど。何か月から受けられる・何回・いくら・助成 | 1    |
| 預け先の事前登録     | 病児保育（テオテの登録と施設登録）・子サポ（説明会と顔合わせ）・緊サポ・ショートステイ              | 1    |

- 子どもの時期は出生から就学前まで。最初の版のデータは 0〜2 歳を厚くする。妊娠中の手続きは入れない
- 発達の目安（離乳食の開始時期など）は初版に入れない（ADR 0003）
- 任意接種は「この月齢から受けられる」「費用・助成・窓口」として出す。「打つべき」「おすすめ」とは書かない。接種するかの判断は親と医師のもの
- 時間が足りないときは、領域ごとではなく件数で削る。病児保育の登録 1 件は必ず残す。削った判断は ADR に残す
- 制度の必要条件（勤め先の雇用保険など）が入力から判定できない項目は、期日だけ出して「対象かは要確認」と印を付ける。追加の入力を求めない

### 出さないもの

[ADR 0002](adr/0002-topic-gaps-left-by-existing-apps.md) のとおり。定期接種のスケジュールと記録・健診・日々の記録・園との連絡・接種や受診をすべきかの判断・離乳食の献立や量・手続きの代行・写真の読み取り。加えて、項目についての質問に答える機能は初版に入れない（ADR 0003）。

## 3. 画面と流れ

スマホで開く Web アプリ。日本語だけ。

1. **最初の設定（1 画面）**: 子どもの生年月日・住んでいる区・親の働き方（親ごとに 1 つ）・保育園に通っているか。任意で入園予定月と第 2 子の予定日。子どもは「もう 1 人足す」で 2 人まで。最後に「毎月 1 日に開く」の案内とホーム画面への追加
2. **見通し（主画面）**: これからの 12 か月を月ごとに並べ、各月に 3 レーンを出す。「起きうること」は生活のイベントの数字（出典つき。病気や合併症の確率は出さない）。「先に済ませること」は期日の近い順の一覧で、各項目は「これから」「今できる」「締切が近い」「過ぎた」のどれかの状態を持ち、過ぎたものは消さず赤で残す。各項目に、開始日と締切・費用と助成・窓口（区に合わせたもの）・出典 URL・確認日。「お金」は給付が入る月と、費用・助成の定額。入園予定月・第 2 子の予定日を変えると見通しが変わる。領域で絞り込める
3. **一言で済みにする**: 画面下の入力欄に「インフル 1 回目打った」「児童手当出した」と書く → Claude が項目・回次・日付の候補を返す → 確認して反映。曖昧なときは候補を出さずに聞き返す。確認せずには反映しない。反映は取り消せる
4. **項目を開く**: 家庭の状況に合わせた短い説明（Claude）と、窓口・出典へのリンク。質問欄は無い
5. **設定**: 家庭のデータの書き出し（JSON）・読み込み・消去。配偶者との共有は書き出しで行う。計算した開始日と締切は iCalendar（.ics）に書き出せ、端末のカレンダーに入れられる（通知の代わり。サーバーは使わない）

## 4. データ

### 家庭のデータ

- ブラウザの中にだけ置く（サーバーに個人情報を置かない。ログインも無い）
- 持つもの: 子ども（生年月日・名前は任意。第 2 子は出産予定日でもよく、「予定」の印を持つ）・区・親の働き方・保育園の有無・入園予定月（任意）・済みの記録
- 済みの記録の単位は「子ども・項目・回次・日付」。取り消せる
- 複数の子どもに広げられる形にし、画面は 2 人まで
- 書き出す JSON の中身は上と同じ。制度データは含めない。読み込み時は形を検証し、合わないものは読まない

### 制度データ

- 開発中に Claude Code のサブエージェントが札幌市・北海道・国の公式ページから起こし、人が確かめて YAML に入れる。実行時はファイルを読むだけで、Claude は公式ページを読まない
- 1 項目が持つもの: id・自治体・領域・名前・対象の条件（月齢の範囲・働き方・保育園の有無・判定できない条件は「要確認」）・開始日と締切の決まり方・準備に要る日数・費用と助成・窓口（区ごとのリンク）・出典 URL・確認日・根拠の抜粋（出典の 1〜2 文。人が確かめるためのもので、Claude の回答には使わない）・補足
- 期日の決まり方は 6 種類: 出生から N 日（出生届・児童手当）／月齢で始まる（接種・病児保育）／毎年の時期（インフルエンザ）／申込の時期（保育園）／前回の完了日から N 日後（複数回の接種の 2 回目以降）／家庭の予定の N 日前（入園予定月の初日・復職予定日。子サポの顔合わせなど。ADR 0005）
- 出典 URL・確認日・根拠の抜粋・期日の決まり方が無い項目はテストで落とす
- 確認日から 90 日を過ぎた項目には「確認が古い」と印を付ける。隠さない
- 制度は札幌市のみ。自治体の欄でほかの市を足せる形にしておく。区で変わるのは窓口と施設へのリンクだけで、制度本体は全市共通で持つ

### 起きうることのデータ

- 見通しの「起きうること」に出す、生活のイベントの数字。`events.yaml` に持つ。種類は 5 つ: 通園できない日数／親が休む日数／流行期／給付が入る月／受診の回数
- 1 件が持つもの: id・種類・名前・対象（月齢・保育園の有無・月）・値と単位と統計の種類・出典 URL・確認日・根拠の抜粋・補足
- 出典は公的機関か査読論文だけ。病気や合併症の確率、ワクチンの効果は持たない（ADR 0003・0005）。出典が取れなかった数字は出さない
- 形は [data/README.md](../data/README.md)

## 5. 計算

- 入力は、基準日（端末の時計の今日、JST）・家庭のデータ（入園予定月・第 2 子の予定日を含む）・制度データ・起きうることのデータの 4 つ
- 出力は、項目ごとの開始日・締切・状態（これから／今できる／締切が近い／過ぎた／済み）と近い順の並び、そして基準日から 12 か月分の月ごとの見通し（その月に当たる起きうること・先に済ませること・お金）
- 第 2 子は予定日を生年月日の代わりに使って計算し、「予定」の印を付ける。入園予定月は「家庭の予定の N 日前」の起点と、保育園の有無が切り替わる月になる
- すべてプログラム（純粋な TypeScript の関数）で計算する。Claude には生成させない。同じ入力なら同じ結果になる
- 月末・年度の境（4/1）・閏年・2 回目以降の接種を、テストの境界ケースにする

## 6. Claude の役割

| 役割             | 送るもの                                                                 | 返るもの                                  | 触らないもの     |
| ---------------- | ------------------------------------------------------------------------ | ----------------------------------------- | ---------------- |
| 一言の解釈       | 一言の本文（200 字まで）・子どもの月齢・候補になる項目の id と名前・回次 | 項目 id・回次・日付の候補、または聞き返し | 反映そのもの     |
| 次の一手の説明文 | 項目の id と名前・開始日と締切・月齢・働き方・保育園の有無               | 「今週はこれ」の短い説明                  | 日付・対象の判定 |
| データの鮮度点検 | 制度 YAML と出典 URL                                                     | 公式ページとの差の報告                    | YAML の書き換え  |

- 送らないもの: 生年月日・区・子どもの名前・済みの記録の全体
- サーバーレス関数は本文をログに残さない。残すのは状態コードと長さだけ
- 説明文の決まり: 「打つべき」「おすすめ」「〜した方がよい」を使わない。制度の事実と期日だけを、その家庭の状況に合わせて短く言う
- 鮮度点検は Claude Managed Agents で作る。11/7 に着手し、間に合わなければ Claude Code のサブエージェントで代用する
- モデルは実装時に claude-api スキルで最新を確かめ、ADR に書く

## 7. 技術と配置

- Next.js + TypeScript。日付計算は画面から切り離した純粋な関数
- Vercel に公開する。Claude の呼び出しだけサーバーレス関数を通し、鍵はサーバー側の環境変数にだけ置く
- 関数の悪用対策: 入力長の上限（一言 200 字）・送信元ごとの頻度の上限・1 日の総呼び出しの上限。上限に達したら Claude の機能だけ止め、一覧と計算は動かし続ける。値は実装時に決める
- Claude が応答しないときも、一覧と計算は動く

## 8. テスト

- 表形式のテストケース: 基準日・生年月日・区・働き方・保育園の有無・入園予定月・第 2 子の予定日 → 出る項目と開始日・締切・状態、月ごとの見通し。CI で回す。月末・4/1・閏年・2 回目の接種・入園予定月を変えたときの期日の移動を含める
- 制度 YAML の形の検証: 出典 URL・確認日・根拠の抜粋・期日の決まり方の欠落を落とす
- 一言の解釈の例: 当たる一言（候補が 1 つに決まる）・曖昧な一言（聞き返す）・関係ない一言（反映しない）をリポジトリに残す
- 制度データの作り方の記録: 公式ページから起こした値と根拠の抜粋を YAML に、誤りを直した経緯をワークログに残す
