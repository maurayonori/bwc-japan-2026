# デモ動画の台本（3 分）

審査では、デモ動画が成果を伝える「ほぼ唯一の手段」とされています。3 分以内に収め、冒頭で「誰の、どんな課題を、どう解くか」が分かるようにします。ここでは時間の割り振りだけを先に決めておき、中身は題材が決まってから書きます。

## 時間の割り振り

| 時間       | 見せること                                                         | 中身       |
| ---------- | ------------------------------------------------------------------ | ---------- |
| 0:00〜0:20 | 誰の、どんな課題か。どれくらい困っているか                         | 「子が熱を出した日に病児保育を使おうとしても、登録していなければ使えない」。事前登録をしていない保護者は 66.5%（東京都）、未登録が使わない理由の 2 位 39.3%（函館市）。第一声: 困った日には間に合わない登録を、先に済ませる |
| 0:20〜0:40 | なぜこの課題なのか（当事者か、どの現場から出発したか）             | 母子モ・ピヨログ・園のアプリを入れても、手続きの期限・任意接種の費用・預け先の登録は役所と市のサイトに散らばっている。10 月に出た LINE の Agent i も TODO を AI が作るだけで、出典も期限の計算も預け先も無い |
| 0:40〜2:10 | 実際に使っている画面。前提知識の無い人にも流れで価値が分かるように | 架空の家庭（2026-07-08 生・母育休中・保育園未定・中央区）を 4 つ入力 → 12 か月の見通し（下の骨組み）→ 一言「保育園の申込出した」で済み → 入園予定月を 2027-04 にすると 3 月に顔合わせ、4 月以降に病欠の目安と給付の終わりが現れる → 項目を開いて出典と確認日 → .ics に書き出す |
| 2:10〜2:40 | Claude をどう使ったか。何ができるようになったか                    | 仕様は Claude Code の質問ツールで 1 問ずつ聞き取り（docs/spec.md）。制度データは領域ごとのサブエージェントが公式ページから起こし、人が選んだ（出典・確認日・根拠の抜粋が全件）。日付と対象の判定はプログラム。Claude は一言の解釈・説明文・鮮度点検（Managed Agents）だけ |
| 2:40〜3:00 | ハッカソンのあと、誰が使い続けるか                                 | 作者の家庭が就学まで使う。札幌の家庭なら保育園に通っていなくても使える。制度は YAML に出典と確認日つきで持ち、鮮度点検で差分を報告する。ほかの市は自治体の欄を足せば広げられる |

## 撮影の前に確かめること

- 画面に映るものは、すべて期間中に作ったもので、このリポジトリにある
- 画面に秘密情報・個人情報・実在の人物のデータが映っていない（架空のデータを使う）
- 音声・字幕・画面の文言が日本語
- 公開設定（審査員と参加者が見られる）にした
