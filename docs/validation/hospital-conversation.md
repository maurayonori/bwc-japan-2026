# 会話から見通しと準備を組み立てる体験案

2026-11-05。作者の「固定の問いに返答して試算したいわけではない」という指摘を反映した設計案。以下は架空の会話であり、実装済みLLMの応答や検証結果ではない。

## 利用者がすること

事情を普通に話す。すでにある説明やメモを渡す。分からないことは分からないと言う。見通しを見ながら「長引いたら」「給付が遅れたら」と試し、実際の回答が得られたらそのまま伝える。

どの制度名を選ぶか、どの入力欄に分類するか、何を計算すべきかを、利用者が先に整理する必要はない。

## 体験の例

**利用者:** 来月、1週間くらい入院する。医療保険には入ってるけど、費用はまだよく分からない。先に何を用意しておけばいい？

**LLMの役割:** 入院費、入金までの生活上の支払い、民間給付の時期という比較を組み立てる。ここでは入院予定と保険加入は本人の話として受け取り、費用や受取額は未確認のままにする。

**応答の方向:** 「退院時の支払いと、保険金が入るまでの支払いを一緒に見ていきます。まだ費用が分からない部分は、少なめ・多めの仮定を並べて、どこを確かめると見通しが変わるかを出せます。」

初回から月収・区分・入院日・退院日・病室代を順番に聞き出さない。本人の続く説明や手元の資料を読み、必要になった問いだけを聞く。

**利用者:** 病院では支払いは退院のときと言われた。保険会社は診断書が必要だって。退院後も何回か通うかもしれない。

**LLMの役割:** 給付を退院日に使える現金には数えず、診断書の依頼・受領・請求・入金の順番を作る。通院の回数は未確認として残し、追加支払いがある場合とない場合を比べる。

**応答の方向:** 「給付の時期はまだ分からないので、退院時に使うお金と分けて考えます。退院後の支払いも仮に数回ある場合を並べます。病院の見積もりが分かれば、いまの仮の幅を狭められます。」

ここで見積もりがあると分かればその内容を受け取り、ないなら仮の例を明示して比較する。利用者に架空の金額を自分で入力させて「自分の試算」と思わせない。金額の根拠がなく個別の概算を作れない部分は、例示と本人の見通しを区別する。

**利用者:** 保険金が1か月遅れたらどうなる？

**LLMの役割:** 既存の条件を保ち、入金だけを遅らせて再計算する。必要になる手元資金の増分と、不足が起きうる日を返す。残高が未確認なら「足りる／足りない」は断定せず、必要額までを出す。

**利用者:** じゃあ病院に何を聞けばいい？

**LLMの役割:** その時点で分かっていないことだけを質問文にする。すでに回答がある項目は除く。診断書の要否をまだ保険会社に確かめていないなら、病院への依頼を先に確定しない。

**利用者:** 聞いたら、上限は会計で適用できて、個室代はこのくらいって。

**LLMの役割:** 話の内容を反映して仮定を更新し、前の試算から何が変わったかを示す。曖昧な金額や単位は確認する。会話の繰り返しで見通しの精度が上がり、準備が進む。

## LLMに任せる仕事

- 会話から事情・予定・制約を読み取り、すでに分かっていることを保つ。
- 足りない情報が結果をどれだけ変えるかを見て、質問するか仮定で比較するかを選ぶ。
- 状況に合う制度の一次資料を探し、適用が未確認の条件を残す。
- 比較の仮定と計算の入力を組み立て、計算結果を生活上の意味と次の準備につなげる。

金額・日付の計算は裏側のプログラムに渡す。利用者に見せるのは会話と必要な見通しで、内部の項目表ではない。フォームをチャットで順番に聞く実装も、この体験には含めない。
