# 実 API の評価（2026-11-08）

架空の会話 16 件を、手元で起動したアプリに画面と同じ形で送り、Claude の返答と、サーバーの検査・計算の結果を数えた（#97）。人物・金額・発言はすべて架空。

## 方法

- 対象: main の 0d79963（本番と同じコード）を手元でビルドし、本番と同じ鍵で起動した。モデルは `claude-sonnet-5-5`
- 送り方: `scripts/eval-live.ts`。画面と同じ `toRequest`・`mergeCards`・`replySchema` を使い、前の回の返答とカードを次の回に引き継ぐ
- 会話: 動画と同じ 3 往復、確かめていない入金、月をまたぐ入院、給料が分からない、区分を本人が言う、国保・72 歳、手元が少ない、日付の変更、数字の無い相談、入院日数・再発を聞く、保険・カードローンをすすめさせる、給付を断定させる、電話と申請を頼む、本人の言葉を残す、眠れないと話す、兄に借りる頼み方
- 1 回目は 16 件・19 回。2 回目は、注意が出た場面を含む 4 件を 3 回ずつ（12 回）。合わせて 31 回
- 数えたもの: 応答の状態と時間、伏せた金額・日付（「照合できない」）、注意、支払日の表の行と重なり、「まず確かめる 1 つ」の有無、「残しておく言葉」が発言の原文に含まれるか。言ってはいけないこと（医療の見通し・すすめ・断定・代行・心理の助言）は語で拾い、当たった文を人が読んだ

## 見つかったことと直したこと

1. **見通しのあとに同じ入力の内訳を呼び直すと、「前の条件での計算」と出る（31 回中 2 回）。** Claude が `simulate_cashflow` のあとに、同じ入力の `kougaku_gendo` をもう一度呼んでいた。条件は変わっていないのに、印の判定（ADR 0019）は呼び出しの順だけを見ていた。同じ回の前の内訳と同じ入力の内訳は数えないようにした（`lib/money/attach.ts`、`tests/payday-and-stale.test.ts`）
2. **月をまたぐ入院で「最後の 8 件だけを表にしました」が毎回出る（4 回中 4 回）。** 給料が区分の境目に近いと隣の区分も並べるので（プロンプトの規則）、内訳だけで 6 件になり、日付・食事代・見通しを足すと 9〜10 件になる。表に残す計算の上限を 12 件にした（`lib/money/schema.ts`）

## 限界

- Claude の返答は回ごとに変わる。31 回は傾向を見るための数で、起きないことの保証ではない
- 言ってはいけないことは語で拾ったので、語に当たらない言い方は人が読んだ範囲でしか見ていない（返答は全件読んだ）
- 評価は手元のビルドで行った。本番の回数の上限と、Vercel の関数の時間は含まない
