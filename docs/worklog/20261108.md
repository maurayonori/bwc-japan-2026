- 決めたこと:
  - 額は、返答でも利用者の発言でも、同じ取り出し方で額の全体ごとに取り出す。円・¥・万・千・億のどれかがあれば額。空白と単位のまざり（「11万 5,690円」「￥12万3千」）は 1 つの額として読み、途中まで重ねて取り出さない。歩・歳・人などが続く数字は額にしない（指摘 1・4・9）
  - 和暦（令和）と、括弧の無い曜日も照らす（指摘 10）
  - 会話の前の返答に書いた額と日付は、そのときに照らし終えた値なので、照合の根拠に残す。置き換えた前の計算をカードに残す案は、表と保存データの形が変わるので採らなかった（指摘 2）
  - 後処理（伏字・注記・案内）のあとの長さを、画面の形の上限に収める。文の終わりで切り、注記は残し、途中で切れた数は残さない（指摘 3）
  - 代行の完了の置き換えは、アプリが行ったと読める文だけにする。本人や家族が主語の文と、カードが写した本人の発言は残す。見出しも検査し、強調の語の無い給付の断定も置き換える（指摘 5・6）
  - お金のカードは、欄ごと決まった文に替えず、照らせない部分だけを伏せる（指摘 7）
  - 返答が書いた「要る額」の範囲は、最新の計算の範囲と照らし、合わなければ注意を出して伏せる。プロンプトは、条件が変わったとき（仮の問いも）は新しい条件の筋書きだけを置き、前の額は「前は ◯ 円でした」と書かせ、差額を書かせない（指摘 8）
  - 保存済みの「残しておく言葉」は、前の版の形（次の行動が決まった文でない）のものだけを、読み込むときに直す。体験例の見出しは作者が書いた架空の文なので、そのまま読む（指摘 11）

## 11/7 22:10 #61 の 2 回目への外部レビューで見つかった 6 件を直し、3 件を Issue に残した（JST）

- やったこと: 統括セッションから受けた 3 回目の依頼（Cursor は「マージしてよい」、Codex は「不可」）に対応した。指摘ごとの再現テストを `tests/review-61.test.ts` の末尾（「3回目」）に 6 件足し、6 件とも指摘どおりの理由で落ちることを確かめてから直した
- 決めたこと:
  - 条件をつけた範囲（「〜場合」「〜なら」「〜とき」）は、条件の語の前の部分を、筋書きの名前か、筋書きを区別する入出金の label に結び付け、その筋書きの範囲と照らす。結び付けられないとき、範囲のあとにだけ条件の語があるときは照らさない（正しい返答を伏せないほうを取る）（指摘 1）
  - 完了の報告は、済ませた人と結び付ける。本人・家族の報告は、本人の発言に同じ報告（同じ人が同じ手続きを）があれば残す。本人の発言をそのまま写した文は返答でも残す。「代わりに」「こちらで」「しておきました」は、「あなたが」があっても置き換える（指摘 2、Cursor の指摘も同じ直し方）
  - 「幅」「前は」の例外は、範囲のすぐあとの「に縮みます」と、範囲と同じ節の前の値の語だけにかける（指摘 3）
  - 「1〜2千円」の左端は、右端の千を借りる（指摘 4）。字数の調整で外す文字に全角の数字と区切りを足し、数の途中で切れたら数ごと外す（指摘 5）
  - 持ち出しの直前に、本人が直していないカードを照らし、照らせない部分を伏せる。根拠は、カードの計算・会話・カードの根拠の引用（指摘 6）
  - 取りこぼし 3 件（小数の千、漢数字の和暦の年、金額でない単位）は #63 に残した。マイルストーンには入れていない
  - ADR 0018 に、上の判断を書き足した
- 確かめたこと（Node 24）: 型、単体 326 件すべて合格、`npm run check:public`（問題なし）、`npm run test:e2e`（build を含む）6 件合格。体験例を会話つきと会話なしで持ち出しても、伏せ字は出ず、文は同じ
